# 침해사고 분석 및 대응


- IDS
    - 오용 탐지
        - 알려진 패턴 기반 탐지
            - 오탐률 낮으나 미탐률 높음
    - 이상 탐지
        - 평균 상태 이탈 감지
            - 오탐률 높으나 미탐률 낮음
    - 호스트 기반 HIDS
        - 호스트 로그 등 기반 탐지
        - 트립와이어 : 호스트 파일시스템 무결성 검사도구
        - 단일 호스트 기반 : 호스트 하나로 탐지
        - 다중 호스트 기반 : 여러 개 호스트 정보 서버에 모아서 탐지
    - 네트워크 기반 NIDS
        - 네트워크 트래픽 패킷 수집 탐지
        - 스노트 : 오픈소스 침입탐지시스템
            - 룰 헤더 : 처리할 패킷 판단 기준 명시
            - 룰 바디 : 패킷 데이터 탐지 위한 규칙 명시
                
                content : 어떤거 찾아?
                
                offset : 어디서부터?
                
                depth : 몇 개?
                
                msg : 로깅 뭐라고 하고싶은데?
                
            - 바이너리 비교법 : 16진수 바이너리 문자
            - 텍스트 비교법 : 아스키 문자
                
                >> 바이너리가 텍스트에 비해 훨씬 유연한 패턴
                
            - 스니퍼 모드 : 단순 패킷 출력
        - 수리카타 : 스노트의 단일 스레드 방식 개선
        - 주로 미러링 모드로 설치(탐지목적이기에)
- IPS
    - 탐지 + 차단
    - 미러링 모드 아닌 인라인 모드로 실행(차단까지 해야하니까)
- 침입차단시스템 (방화벽)
    - 패킷 필터링 : 네트워크 패킷들을 규칙에 따라 차단 or 허용
    - iptables : 현재 시스템 상태 검사, 로깅 등, 방화벽 장비에서 사용
        - 리눅스 커널에 내장된 패킷 필터링 기능 제공하는 netfilter 기능 관리 툴
    - 패킷 헤더의 출발지 IP 주소, 목적지 IP 주소, 출발지 포트번호, 목적지 포트번호, 프로토콜 참조
    - 상태 검사 기능 : 프로토콜의 상태정보까지 일정시간 유지
        
        >> 상태검사 방화벽 : 기존 패킷 필터링 기능에 세션 추적 기능 추가
        
        → 순서에 위배되는 패킷 모두 차단
        
    - 배스천 호스트 : 방화벽 시스템 관리자가 중점 관리하는 시스템
    - 구현 방식
        - 패킷 필터링 방식
            - IP, 포트번호, 프로토콜 기반 필터링
        - 상태 검사 방식
            - 패킷 필터링 + 상태검사
        - 애플리케이션 방식
            - 응용 계층 서비스 중계, 서비스 제어, 사용자 인증 등 수행
        - 회선 게이트웨이 방식
            - 전송 계층 트래픽 중계, 연결 제어 수행
    - 구축 방식
        - 스크리닝 라우터 방식
            - 패킷 필터링 함께하는 라우터 방식
        - 듀얼 홈드 게이트웨이 방식
            - 두 개의 배스천 호스트로 한 쪽은 외부, 한 쪽은 내부에서 접근제어 수행
        - 스크린드 호스트 게이트웨이 방식
            - 외부 스크리닝 라우터 + 내부 싱글/듀얼 홈드 게이트웨이
        - 스크린드 서브넷 게이트웨이 방식
            - 스크리닝 라우터 사이 듀얼 홈드 게이트웨이
            - DMZ 운영
    - NAC : 네트워크 액세스 컨트롤, 네트워크 통제 기능
        - 허가받지 않은 단말이나 악성코드 감염 단말의 접속 사전 차단
        - 보안성 강제 및 필수 프로그램 설치 유도
        - 네트워크 접속 인증, 네트워크 자산 접근권한 통제 등 관리
    - SSO : 한 번의 인증으로 재인증 없이 자동인증
    - 웹 방화벽 WAF : 탐지 및 차단 장비
        - SQL 인젝션, XSS, 등 탐지하고 차단하는 기능
        - 캐슬 : KISA 제공 공개 웹 방화벽
        - 웹나이트 : MS사의 IIS 웹 방화벽
        - ModSecurity : 트러스트웨이브사의 아파치, IIS 웹 방화벽
    - EDR : 엔드포인트의 이상행위 탐지, 차단
    - DLP : 엔트포인트에 에이전트 설치하여 중요 문서 탐지
    - UTM : 방화벽, IDS 등 장비 통합 제공/여러 장비 하나의 장비로
    - ESM : 방화벽, IDS 등 의 관리 시스템 모음
        - 구성요소
            - EMS 에이전트 : 관리 대상에 설치되어 EMS 매니저로 로그 보냄
            - EMS 매니저 : 정보 저장하고 분석 결과 콘솔로 보냄
            - EMS 콘솔 : 전달받은 정보를 시각과, 리포팅, 위 두 개 제어
    - SIEM : 보안장비를 넘어서 다양한 로그 분석하여 보안위협 사전차단
        
        ESM의 업그레이드 버전 느낌
        
        - 로그 수집
        - 로그 변환 : 다양한 로그 형식 표준 포맷으로 변환
        - 로그 분류 : 그룹핑하여 하나로 취합
        - 로그 분석
    - 트러스트 존 : CPU 안에 독립적 보안구역, 보안 필요한 것만 보안구역에서
    - DRM : 디지털 콘텐츠 저작권 보호위한 모든 기술
        - 복사 방지, 위변조 방지 등의 다양한 기술과 이를 위한 장치 존재
    - SOAR : 사이버 공격 방지 및 대응 자동화, 지능형 공격에 효과적 대응
    - 사이버 위협 인텔리전스
        - SIEM과 연계하여 위협 분석 지원, APT 같은 위협에 효과적 대응
    - 보안관제 모니터링 방법
        - 보안장비 모니터링 : 방화벽, IDS등 확인
        - 서버 모니터링 : 주요 시스템 Health Check 모니터링 결과 확인, 가용성 확보
        - 트래픽 모니터링 : 패킷 흐름 상태 확인
    - 보안 솔루션 취약점
        - 계정 관리
            - 보안장비 기본 계정 변경 취약점
            - 보안장비 기본 패스워드 변경 취약점
            - 보안장비 계정별 권한 설정 취약점
            - 보안장비 계정관리 취약점 : 불필요한 계정은 삭제하자.
        - 접근 관리
            - 보안장비 원격관리 접근 통제 취약점 : 원격 IP 접속 접근통제 필
            - 보안장비 보안 접속 취약점 : SSH, HTTPS 꼭 사용
            - 세션 타임아웃 설정 취약점 : 세션 타임아웃 꼭 설정
    - 인터넷 사이버 위기 경보 단계
        - 정상 단계
        - 관심 단계 : 야 이거 일 터지겠는데?
        - 주의 단계 : 야 여기 일 터졌다.
        - 경계 단계 : 야 이거 퍼지기 시작한다..
        - 심각 단계 : 야.. 이거 다 퍼졌다.
    - 퍼저(퍼징 도구)
        - 애플리케이션의 보안취약점 찾아내기 위한 도구
        - 소프트웨어 오류를 유발해 취약점 찾아내는 목적
    - 트립와이어 : 무결성 점검 도구
    - 네서스 : 알려진 취약점 점검하여 다양한 형태로 보고서 상세 작성
    - 닉토 : 취약점 점검도구, 다양한 형태 취약점 스캔
    - 백도어 : 개발자나 관리자의 의도 하에 남겨진 보안 허점
        - 가끔 해커들이 백도어 파일에 읽기전용 설정해놓는 경우 있음
            
            → chattr + iaA 파일 읽기전용/내용 추가만 허용/접근시간 고정
            
            >> lsattr로 속성 확인 가능
            
    - proc 파일 시스템 : 커널이 사용중인 프로세스 자원, 커널 파라미터 등에 대한 상태정보 관리, 디스크상 존재X ⇒ 가상 파일시스템(메모리 존재)
        
        >> 루트킷 이용한 공격시 /proc 파일 시스템 이용하여 탐지
        
    - strace 명령 : 프로세스의 시스템 콜 명령 추적
- 레지스터
    - RDI > RSI > RDX > RCX > R8 > R9 순서로 레지스터에 저장
- 윈도우 PE 파일
    - .text : 코드 담긴 섹션
    - .data : 변수 담긴 섹션
    - .rdata : 읽기 전용 상수 섹션
    - .bss : 초기화되지 않은 전역변수
    - .idata : 임포트 할 DDL
    - .edata : 익스포트 할 DDL
    - .rsrc : 다이얼로그, 아이콘, 커서 등 윈도우 애플리케이션 리소스
- 윈도우 레지스트리 최상위 루트키
    - HKCR : 파일 확장명과 응용프로그램 연결정보 등
    - HKCU : 현재 로그인중인 사용자 환경설정 정보
    - HKLM : 시스템 전체에 적용되는 설정 데이터
    - HKU : 다중 사용자 환경에서 환경설정 정보
    - HKCC : 현재 윈도우의 하드웨어 프로필 정보
- DBD 공격 : 웹사이트 단순 방문이나 배너 클릭만으로도 악성코드 다운로드되는 공격
- 난독화 : 코드의 가독성을 낮춰 분석 어렵게 하기 위하였으나, 되려 해커들이 악성코드 난독화를 위해 사용
- 인터넷 익스플로서 임시파일 유형
    - 임시 인터넷 객체 ~ Program Files
    - 임시 인터넷 파일(캐시) ~ Internet Files
    - 열어본 페이지 ~ History
    - 임시 쿠키 파일 ~ COOKIES

- 멀버타이징 : 악성코드 + 광고
    
    온라인 광고를 통한 악성코드 전파
    
- 가짜 악성코드
    - 혹스 : 가짜 바이러스, 보통 비트코인 요구
    - 조크 : 사용자 놀라게 하는 프로그램
- 메인 악성코드
    - 웜 : 자가복제 O, 독립실행 O
    - 바이러스 : 자가복제 O, 독립실행 X
    - 트로이목마 : 자가복제 X, 독릭실행 O, 정상 기능 프로그램 가장
- 복합 악성코드
    - 키로거 공격 : 컴퓨터에 몰래 설치되어 사용자의 키보드 입력 탐지
    - 다운로더 : 악성코드가 지정한 주소에 접속해서 악성코드 다운로드
    - 드롭퍼 : 악성코드가 자신 내부에 있는 상태로 다운로더처럼 우회접속하여 생성
        - 인젝터 : 드롭퍼의 일종, 파일 없이 프로세스 생성하여 메모리 상주
- 악성코드 분석방법
    - 정적 분석 : 소스코드 등을 가지고 분석
    - 동적 분석 : 샌드박스 환경에서 실행시켜 분석
- 애플리케이션 취약점 분석방법
    - 블랙박스 테스트 : 외부 인터페이스 구조 보고 분석
    - 화이트박스 테스트 : 내부 소스코드 보고 분석
- 야라(YARA) : 악성코드의 패턴 분석하여 식별
- 슬랙 공간 : 물리적으로는 할당된 공간이지만 논리적으로는 사용되지 않는 공간
    - 램 슬랙 : 램 데이타 저장매체 기록시 나타남
    - 드라이브 슬랙 : 클러스터 사용으로 낭비되는 공간
    - 파일시스템 슬랙 : 파일시스템의 마지막 부분에 사용할 수 없는 영역
    - 볼륨 슬랙 : 파티션으로 인해 낭비되는 영역
- 공급망 공격
    - 개발사의 네트워크 침투하여 소스코드 변경 → 일반 PC 소프트웨어 설치나 업데이트시 악성코드 감염
- DDE 프로토콜 : MS 오피스간 데이터 교환 프로토콜
    
    >> 최근 이 곳에도 악성코드 시도 수차례 존재
    
- APT : 지형 지속 공격
    - 워터링 홀 : 피해자가 자주 가는 웹 사이트 중 취약점 있는 곳에 리다이렉트로 악성코드 사이트 진입 유도 (악성코드 사이트는 항시 대기)
    - 스피어피싱 : 특정인이나 조직을 표적으로 신뢰하는 발신인이 보낸것처럼 위장메일 송신
    - 크립토재킹 : 일반 컴퓨터에 주인 몰래 악성코드 설치하여 암호화폐 채굴
    - 제로데이 공격 : 취약점 발견과 패치 사이의 간극 이용한 공격
    - 사이버 킬 체인 : APT 대비책, 해킹 과정중 하나만 박살내도 해킹은 이뤄지지 않는다
- MITRE ATT&CK : 마이터 사의 프레임워크
- 풋 프린팅 : 해킹 전 정보수집 활동
- TEMPEST : 전자기기로부터 누설되는 전자파 도청 기술, 이의 방어대책 수립 기술
- 허니팟 : 해커 유도 위한 가짜 시스템, 해킹 경로 분석 용이
    - 허니넷 : 여러 개의 허니팟으로 구성
- 핫픽스 : 취약점 등 긴급 패치 프로그램
- 업데이트 : 컴퓨터 향상 위해 추가되는 소프트웨어
- CVE 취약점 표기법 : 동일한 취약성에 대해 해커와 보안업체간의 명칭 차이 표준화
    - CVE-발생년도-취약점 번호
    - CVSS : CVE 평가 체계
    - CWE : 소프트웨어 보안 취약점 목록화
    - CWSS : CWE 평가 체계
- 역추적 기술 : 해커 위치 실시간 추적, 해커 송신지 추적
    - TCP 연결 역추적
        - 호스트 기반 연결 역추적 기술 : 역추적 위한 모듈이 인터넷상의 호스트들에 존재
        - 네트워크 기반 연결 역추적 기술 : 네트워크 상의 패킷의 정보 추출
    - IP 패킷 역추적
        - 해커의 패킷에 라우터 기록하는 패킷 표시 기법 사용
    - 하트블리드 취약점
        - OpenSSL 서버 외부에서 메모리데이터 탈취
        - 하트비트라는 TLS 확장 프로토콜 구현 과정에서 발생
    - POODLE 취약점
        - SSL/TLS 협상시 버전 다운그레이드 공격
    - NTP 증복 DDos 공격
        - NTP : 네트워크 타임 프로토콜 : 시스템 시간 동기화
            
            >> UDP 123 포트 사용
            
        - monlist 기능을 통해 DDos 공격 발생 가능성 발견 > 업데잍 권고
            
            monlist : 최근 접속 클라이언트 주소정보 전송 기능
            
        - date 명령어 : 현재 호스트의 날짜와 시간 확인
        - ntpdate 명령어 : 원격지에 있는 NTP 서버를 통해 현재 호스트의 날짜 및 시간 동기화
        - Log4j 취약점 : JAVA 사용시 발생 취약점
        - SSDP 증폭공격 : IoT 기기 검색 요청 조작 → 기기로부터 발생하는 큰 응답패킷 호스트에 전달

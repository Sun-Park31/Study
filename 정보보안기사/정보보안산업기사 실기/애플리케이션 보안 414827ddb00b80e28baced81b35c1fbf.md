- DNS 53
    - 도메인 서버의 Zone 파일에 DB 저장
        - 도메인을 DNS 서버에 등록하는 존 설정 & DNS 서버에 서비스 정보 입력하는 리소스 레코드 설정
    - 도메인 IP 쌍 hosts 파일에 저장
    - 파밍 : hosts 파일, DNS 수정 공격
    - ipconfig /displaydns : 로컬 DNS 캐시 정보 조회
    - ipconfig /flushdns : 로컬 DNS 캐시 정보 삭제
    - resolv.conf : 구글 DNS나 KT DNS 등 서버 설정
    - hosts.ics : hosts와 비슷한 성질이나, 순위 더 높음
        
        DNS 캐시 참조 →hosts.ics 참조 → hosts 참조 → DNS 서버 질의
        
        캐시에 묻기 > 없으면 Authoritative에 질의
        
    - UDP/TCP 프로토콜 사용
    - 반복질의 대비 위해 캐시 사용(유효기간 TTL) ⇒ 캐시 DNS 서버
    - named.conf (존 설정 파일) : DNS 버전정보 언노운해서 가리기
    - DNS 캐시 포이즈닝 : DNS 서버(일반적으로 DNS 캐시)에 조작된 쿼리 전송
        
        ⇒ SQL 인젝션 공격 >> **ENSSEC로 방어**한다.
        
    - 슬레이브 서버에 권한 부여
        
        named.conf에 allow-transfer IP주소 해서 존전송 허용

        -p 옵션에는 프로토콜 종류인 tcp, -dport 옵션에는 포트넘버인 53
        
    - CNAME : 서브도메인 설정인자
        
        dns1 1800 IN dns2 : dns1도 dns2로 들어갈 수 있다.
        
        서브도메인 하이재킹 : CNAME 설정한 채로 서비스 이용 중지시 공격자가 서브도메인을 위조된 IP로 연결하여 악성 사이트 유입 유도
        
    - dig와 nslookup 사용으로 정보 확인 가능

    - 연결 방식
        - 쿠키 방식 : 클라이언트에 정보 저장
        - 세션 방식 : 서버에 정보 저장

    - HTTP 상태코드
        - information
            - 100 Continue 계속해라
        - Success
            - 200 OK 니 요청 수행했다
            - 201 Created
            - 202 Accepted
        - Redirection( 니가 요청한거 위치 변경됐으니까 다시 명령해)
            - 301 Moved Premanently 요청한거 자리 아예 바꿨다
            - 302 Found 요청한거 자리 임시로 바꿨다
            - 304 Not Modified 그대로 있으니 로컬캐시꺼 써라
        - Client Error
            - 400 Bad Request
            - 401 Unauthorized 니 권한 없다
            - 403 Forbidden 자원 차단됐다
            - 404 Not Found
            - 408 Request Timeout 니 너무 오래걸렸다
        - Server Error
            - 500 Internal Server Error 내부 서버 오류다
            - 501 Not Implemented 우리 서버가 모지라다
            - 503 Service Unavailable 과부하 걸려있거나 중단 상태다
            - 504 Gateway Timeout 게이트웨이에서부터 걸렸다
            - 505 HTTP Version Not Supported
- FTP
    - ftpusers : FTP 사용자 접근제한 목록
    - 동작모드
        - 능동모드 : 서버가 인증 요청 및 데이터 송수신 요청
            
            클라이언트쪽에 방화벽 설정 안되어있으면 서비스 불가
            
            >> 제어채널 21/tcp 데이터채녈 20/tcp
            
        - 수동모드 : 클라이언트가 인증 요청 및 데이터 송수신 요청
            
            서버쪽에 방화벽 설정 안되어있으면 서비스 불가
            
            >> 제어채널 21/tcp 데이터채널 1024/tcp 이상 허용
            
        
        >> 인터넷 환경에서는 서버 방화벽 관리가 무조건 효율적이므로 수동모드 사용

        익명의 FTP로 시스템 포트, 호스트 스캔 가능
        
    - TFTP : udp/69  사용하는 인증 없는 송수신 프로토콜
        - secure 모드 설정
            
            inetd.conf
            
            tftp dhram udp wait root /usr/sbin/tftpd in.tftpd -s /tftpboot
            
        - TFTP 공격 : 인증과정 없는 허점 노려 공격
        - Anonymous FTP 공격 : 패스워드 요구 안하는 허점 공격, 서버 쓰기 공격 >실제 Anonymous 로그인 이름 존재
        - FTP Bounce 공격 : 목적지 검사 안하는 허점 공격, 포트, 호스트 스캔

            - 저장형 XSS : DB 같은 곳에 악성 스크립트 심기 > 데이타 요청 시 스크립트 실행

    - A10. 서버 측 요청 위조
        
        SSRF 결함 : 웹 서버가 사용자의 URL(약간 명령어) 검증 없이 요청 그대로 제공 (여기서 주요 정보 유출)
        
        >> 취약점 대응 위해서는 데이타 입력값은 화이트 리스트로, URL 입력값은 블랙 리스트로 필터링한다.
        
        cf) CSRF 결함 : 웹 서버에 기 로그인된 PC에 명령어 전달, PC에게 별 의심 없이 세션 제공 (공격자가 원하는 작업 처리)
        
        >> XSS와 비슷한 공격방식
        
        >> 취약점 대응 위해서는 GET 보다 POST 사용, 프로그램 사이에 토큰 사용, 세션검증도 함께함.
        
    - 웹 프록시 : 웹 이용한 해킹 도구, HTTP Request, Response 가로채 필터링 우회 혹은 전송 데이터 조작 > 웹 데이터 탈취
    - 파일 업로드 공격 : 스크립트 파일 등과 같은 것 서버에 업로드 해서 주요 정보 변경 혹은 내부 명령어 실행
        
        >> 웹쉘 사용 (이게 바로 스크립트 파일)
        
    - 파일 다운로드 공격 : 디렉터리 뒤로가기를 이용해 접근 권한 없는 곳의 데이타 요청
        
        https://www.me.you/notice/download.jsp?file=passwd&path=../../../../../etc/passwd
        
    - 딥링크 : 웹상에 있는 그림이나 링크 클릭시 공격자의 유도 URL로 접속 > 개인정보 유출
    - 캡차 : 알아보기 힘든 사람인증 이미지 기술

- 데이터베이스 보안
    - 위협
        - 집성 : 낮은 보안등급 정보 모아서 높은 보안등급 정보 알아내기
        - 추론 : 보안 분류 없는 정보에 접근하여 기밀정보 유추
    - 통제 방법
        - 접근 통제 : 인증 사용자에 한해 내부정보 접근 허용
        - 추론 통제 : 추론 방어 : 통계적 자료로 다른 자료 공개 제어
        - 흐름 통제 : 집성 방어 : 높은곳에서 낮은 곳으로 흐르는 정보 통제
    - 보안을 위한 요구사항 5가지
        - 부적절한 접근 통제
        - 추론 방지
        - 데이터 무결성
        - 감사 기능 : 로그 생성
        - 사용자 인증
    - 권한 관리
        - GRANT 권한 ON 데이터베이스 객체 TO 사용자
        - REVOKE 권한 ON 데이터베이스 객체 FROM 사용자
        - DENY 권한 ON 데이터베이스 객체 TO 사용자
            
            DENY GRANT 중복시 DENY 우선

- 업데이트 : 컴퓨터 향상 위해 추가되는 소프트웨어
- CVE 취약점 표기법 : 동일한 취약성에 대해 해커와 보안업체간의 명칭 차이 표준화
    - CVE-발생년도-취약점 번호
    - CVSS : CVE 평가 체계
    - CWE : 소프트웨어 보안 취약점 목록화
    - CWSS : CWE 평가 체계
- 역추적 기술 : 해커 위치 실시간 추적, 해커 송신지 추적
    - TCP 연결 역추적
        - 호스트 기반 연결 역추적 기술 : 역추적 위한 모듈이 인터넷상의 호스트들에 존재
        - 네트워크 기반 연결 역추적 기술 : 네트워크 상의 패킷의 정보 추출
    - IP 패킷 역추적
        - 해커의 패킷에 라우터 기록하는 패킷 표시 기법 사용
    - 하트블리드 취약점
        - OpenSSL 서버 외부에서 메모리데이터 탈취
        - 하트비트라는 TLS 확장 프로토콜 구현 과정에서 발생
    - POODLE 취약점
        - SSL/TLS 협상시 버전 다운그레이드 공격
    - NTP 증복 DDos 공격
        - NTP : 네트워크 타임 프로토콜 : 시스템 시간 동기화
            
            >> UDP 123 VHXM TKDYD
            
        - monlist 기능을 통해 DDos 공격 발생 가능성 발견 > 업데잍 권고
            
            monlist : 최근 접속 클라이언트 주소정보 전송 기능
            
        - date 명령어 : 현재 호스트의 날짜와 시간 확인
        - ntpdate 명령어 : 원격지에 있는 NTP 서버를 통해 현재 호스트의 날짜 및 시간 동기화
        - Log4j 취약점 : JAVA 사용시 발생 취약점
        - SSDP 증폭공격 : IoT 기기 검색 요청 조작 → 기기로부터 발생하는 큰 응답패킷 호스트에 전달

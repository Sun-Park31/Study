# 정리


## Winser

- 계정 관리 방식
    - 워크그룹
        - P2P
    - 도메인
        - AD에 저장
- 로컬 사용자 계정은 %SystemRoot%\System32\config\**SAM** 에 저장
- 로그
    - 애플리케이션 로그 : 프로그램, 앱 오류(앱 충돌 등)
        - %SystemRoot%\System32\winevt\Logs\**application.evnt**
        - Appication error, Start service, Add/Del member in group
    - 시스템 로그 : 하드웨어, OS 기록, 블루스크린이나 부팅, 종료 등
        - %SystemRoot%\System32\winevt\Logs\**system.evnt**
        - System start/half, RDP(Remote Desktop Protocol) connection(원격 데스크탑 접속)
    - 보안 로그 : 로그인(로그온) 성공, 실패 기록, 권한 변경 등
        - %SystemRoot%\System32\winevt\Logs\**security.evnt**
        - Attempt login, Login Success/Fail, Network Login, Create Process, Service install, Start Windows, Off the Windows
    
    >> 관리 도구는 이벤트 뷰어(이벤트 로그 파일 열어서 보는 곳)(`Win + R`을 누른 뒤 `eventvwr.msc`를 입력)
    
- 감사 정책 : 어떤 로그를 남길지 정의한 규칙
    
    >> `win + R` 하고 `secpol.msc`로 감사 정책 설정
    
    - 파일, 디렉터리 등의 객체 접근 성공 실패 여부 : **개체 액세스**
    - 계정 관리에 관한 이벤트 성공/실패 로그 기록 : **계정 관리**
    - 로컬 계정에 대한 로그온/오프 성공 실패 여부 : **로그온 이벤트**
    - 도메인 계정에 대한 로그온/오프 성공 실패 여부 : **계정 로그온 이벤트**
    - 권한 사용 성/패 여부, 사용자 권한 이용할 때마다 생성 : **권한 사용**
    - AD 개체의 시스템 엑세스 목록의 사용자 액세스 시도시 로그? : **디렉터리 서비스 액세스**
    - 시스템 시작, 종료, 보안로그 영향 이벤트 감사? : **시스템 이벤트**
    - 감사 정책 변경의 성/패 여부 : **정책 변경**
    - 프로세스 추적한 정보 감사? : **프로세스 추적**
- 윈도우 시스템 주요 기본 그룹
    - **Administraors** : 모든 권한 존재 그룹
    - Account Oprators : 계정 관리 그룹
    - **Backup Operators** : 백업을 위해 모든 시스템과 파일 디렉터리 접근 가능 그룹
    - **Guests** : 도메인 사용 불가, 시스템 변경 불가 그룹
    - Print Operators : 도메인 프린터 접근 가능 그룹
    - **Power Users** : 디렉터리, 네트워크 공유, 표준 시간 조정 등과 같은 일부 관리 권한 소유 그룹
    - Replicator : 도메인 있는 파일 복제 가능 그룹
    - Server Operators : 도메인 서버 관리 권한 소유 그룹
    - **Users** : 일반 사용자 그룹, 사용자 환경은 직접 만들어도 설정 가능 항목 제한.
- 암호화 방식
    - 비트로커 : 볼륨 암호화 기능, TPM(신뢰할 수 있는 플랫폼 모듈) 사용하여 초기 시작 구성요소의 무결성 검사 암호화 방식, 물리적 도난 위험 차단.
        - TPM : 하드/소프트/펌웨어 검사 전용 칩, 승인 없는 변경 감지시 PC 제한모드로 부팅.
- net 명령어
    - net user : 전체 로컬 계정 정보 확인
    - net user [계정명] : 해당 계정의 속성 확인
    - 계정의 속성에는 ‘계정 사용 안함’ 존재
        - net user [계정명] /active:yes : 계정 사용 활성화
        - net user [계정명] /active:no : 계정 사용 비활성화(=**계정 사용 안함**)
    - net user A B /ADD : 계정 A를 패스워드 B로 하여 생성(B는 명령어 실행 후 암호화)
    - net localgroup [그룹명] [계정명] /ADD(Delete) : 그룹에 계정 넣기
- 취약점과 보안 공격
    - **Null Session 취약점** : 네트워크에 연결된 윈도우 시스템 간 아이디/패스워드 없이(=Null) 다른 시스템에 접속 가능 > 정보 탈취 위험 증가
    - 패스워드 크래킹 공격
        - **Dictionary Attack** : 자주 쓰는 단어 사전 파일로, 자동화 툴로 대입하여 일치여부 확인
        - **Brute Force Attack** : 패스워드 무작위로 대입
            - **크리덴셜 스터핑** : 공격 대상의 로그인 자격증명 탈취하여 다른 사이트 인증 시스템에 무작위 대입
        - **Hybrid Attack** : 위 두 가지 혼합. 사전파일에 문자열 추가.
    - **Pass the Hash** 공격
        - 공격 대상의 해시 알아내어 패스워드 없이 해시 만으로 인증 시도
        - 미미카츠(계정의 자격증명(ID, PW 등) 수집 가능 도구) 사용
    - PATH 설정
        - 환경변수에 . 들어가있으면 위험함. 뒤로 옮기거나 삭제.
- 보안 OS
    - 메모리 보호, 파일 보호, 접근통제, 사용자 인증
    - 메모리, 공유 객체 보호
    - OS 보안을 위한 분리
        - 물리적 분리 : 사용자별로 별도의 장비만 사용 > 실용성 떨어짐.
        - 시간적 분리 : 프로세스 한 번에 하나 > 동시 실행 원인의 보안 문제 제거
        - 논리적 분리 : 프로세스 별 논리구역 할당
        - 암호적 분리 : 내부 정보는 외부에서 못 봄
    - 구성요소
        - 보안 커널 : SKDB를 통해 접근을 통제하고 로그를 생성하는 커널
        - 참조 모니터 : 보안 커널의 핵심 모듈, 보안 정책 시행, 주/객체 사이 시스템 콜 감시.
- **인터럽트에 의한 입출력**
    - **CPU가 인터럽트 신호 받으면 PC 레지스터에 있는 복귀 주소를 스택에 저장하고 인터럽트 서비스 루틴의 시작 주소 PC 레지스터로 옮겨 시작.**

## LINUX(UNIX)

- 3가지 핵심
    - 커널 : 유닉스의 핵심, 메모리 상주하며 컴퓨터 자원 관리
    - 쉘 : 커널과 사용자 간 인터페이스, 사용자의 명령어에 따라 프로그램 실행
    - 파일 시스템 : 디렉터리, 서브 디렉터리, 파일 등의 트리형 계층구조 제공
- 컴파일 : 고급언어 (C언어 등)>기계어 (010011)
    - 컴파일 방식
        - 정적 링크 : 정적 라이브러리에 있는 파일 사용 (실행 파일 내에 라이브러리 함수 포함)
        - 동적 링크 : 동적 라이브러리에 있는 파일 사용 (프로그램 실행 시 외부 라이브러리 동적 링크) > 주소 연결 테이블인 PLT, 함수의 실제 주소 저장된 GOT 참조
- init 프로세스 : 시스템 부팅의 마지막단계 실행, /etc/inittab 읽어 런 레벨 따라 초기화, 고아 프롤세스의 대리모
- 출력방향 재지정
    - 1 : STDOUT : 표준 출력 아웃
    - 2 : STDERR : 표준 에러 아웃
    - >> : 원 내용 아래에 붙여넣기, > : 원 내용 없애고 붙여넣기
- 문맥 교환
    - 문맥 : 프로세스와 관련된 총집합
    - 문맥 교환 : PCB에 프로세스의 문맥을 저장하고, 재적재 하는 겻
    - PCB : 프로세스 제어 블록 : PID, 문맥 저장영역, ps의 상태, 순의, 할당 메모리 정보 저장
- 프로세스 (실행 + 실행 환경)
    - 프로세스 관련 명령어
        - top : 시스템의 전체적 상황 모니터일
        - pstree : 프로세스 트리구조로 확인
        - (re)nice : 우선순위 조절
    - 준비 상태
    - 실행 상태
    - 대기 상태
    - 종료 상태
    - 교착 상태
    - 프로세스의 생성과 함께 PCB도 생성, 완료되면 제거
    - 스레드 : 프로세스에서 실행 개념만 분리, 제어의 흐름(시간)
- 교착상태
    - 교착상태의 조건
        - 상호 배제 : 자원은 한 번에 한 프로세스만 일 때
        - 점유와 대기 : 갖고 있으면서 다른거 대기
        - 비선점 : 다른 ps는 자원 회수 불가
        - 환형 대기 : 점유와 대기가 두 프로세스 간 서로 하는 중
- 스래싱 : 램 페이지 교체가 프로세스 처리시간보다 오래 걸리는 현상
    
    >> 워킹세트(참조 페이지 집합) 유지 필수
    
- 메모리
    - 스왑 공간 : 메모리 부족할 때 디스크 상 공간 마치 메모리처럼
    - 페이지 교체 알고리즘
        - LRU : 리스트 리센틀리 유즈드 : 적은 최근 사용 없앰
            
            페이지마다 카운터 존재
            
        - LFU : 리스트 프리퀀틀리 유즈드 : 적은 조회수 없앰
        - NUR : 낫 유즈드 리센틀리 : 최근 사용 안함 없앰
            
            참조비트와 교체비트 사용
            
        - FIFO : 처음 I 처음 O
    - 캐시 메모리 : RAM과 CPU 속도 차이 보완 : 핵심데이터 캐시에 미리 넣어두고 꺼내 쓰기
    - 버퍼 메모리 : 빠른 장치와 느린 장치 데이터 전송 매끄럽게 : 데이터 과하게 받으면 저장했다가 차차 쓰기
        - 스택 : 함수 호출시 자동 할당 > 스택 공격은 복귀주소가 보통 변경
        - 힙 : 사용자가 직접 할당 > 힙 공격은 데이터나 함수 주소 보통 변경
        - 버퍼 오버플로우 : 버퍼 조차도 못 견딜 정도로 데이타 많이 때려박기
            
            >> ASLR로 스택이나 힙 메모리주소 프로세스 공간에 랜덤으로 배치, 실행마다 주소 바뀌어서 오버플공격 어려워짐.
            
            echo 2 > /proc/sys/kernel/ramdomize_va_space
            
            ASLR  명령어, 0은 미사용, 1은 힙 빼고 사용, 2는 메모리 전부 사용
            
            ASLR  명령어, 0은 미사용, 1은 힙 빼고 사용, 2는 메모리 전부 사용
            
            >> 스택가드로 프로그램의 복귀 주소와 변수 사이에 카나리 워드 삽입, 변경되었다면 오버플가정, 프로그램 중단
            
            >>스택쉴드로 리턴주소를 Global RET에 저장, 함수 종료시 비교하여 다를 경우 프로그램 종료

                    chmod 4777/2777 u+s >> -(일반파일, d(디렉토리), l(링크), b, c이 있음)rwsrwxrwx가 됨.(대문자라면 권한 행사는 불가한 상태, 원래 실행권한 없는 상태였었다.)

                d rwx r-x r-x 5 root root 59 2016-01-24 12:30 me.dat
                
                파일 종류 및 접근 권한/ 하드링크수/ 소유주/ 소유그룹/ 크기/ 최종수정일/ 파일명
                
        - PAM : 인증모듈을 외부 공유 라이브러리에서 사용
            - 모듈 유형
                - auth : 계정 비밀번호 검증 등 신원 확인
                - account : 계정의 유효성 검증
                - password : 계정의 비밀번호 설정 변경 관장
                - session : 계정 인증 전후 수행작업 지정
            - 제어 방식
                - requisite : 실패 즉시 거부
                - required : 실패해도 모듈 다 하고 거부
                - sufficient : 모듈 아무거나 성공하면 허용
                - optional : 인증 성패 무시
                - include : 다른 PAM 파일 포함
            - 레드햇의 PAM 비밀번호 설정 조건
                - deny=N : N회 실패시 계정 잠금
                - unlock_time=M : 실패 후 N초 동안 계정 잠금 후 해제
                - no_magic_root/even_deny_root : 루트는 잠금 설정 적용 X/ 루트일지라도 잠금 설정 적용
                - reset : 접속 시도 성공시 실패 횟수 초기화
                - retry=N : 비밀번호 변경시 입력기회 N번 부여
                - lcredit=-1 로워/최소 소문자 수
                - ucredit=-1 업퍼/최소 대문자 수
                - dcredit=-1 최소 수자 수
                - ocredit—1 최소 특수문자 수
                - minlen=8 최소 길이
                - difok=N 기존 패스워드와 비교
        - inetd 서비스(슈퍼 데몬)

            - hosts.deny : 서비스와 접근 거부 목록

            - sadmind : 원격지에서 시스템 관리와 모니터링
            - rexd : 원격에서 서버 명령어 실행
            - ruserd : 현재 네트워크 사용자 리스트 반환
        - rsync 동기화 프로그램

        - syslogd : 로그 관리 시스템
            
            syslog.conf 파일 수정으로 로그 파일들의 수정 가능
            
            syslog.conf의 형식 : 로그 남길 요소(* 하면 올). 지정수준(수준 이상 빡센 문제 로그기록)  로그 남길 위치
            
            - 로그 수준
                - Emergency : 다 조진 상황
                - alert : 다 조지진 않았지만 곧 조질 상황(주로 소프트웨어)
                - Critical : 당장 조질 것 같지는 않지만, 조질 미래가 예상되는 상황 (주로 하드웨어)
                - Error : 일반적 에러
                - Warning : 신경써서 조치는 해야하는 상황
                - Notice : 굳이 신경까지는 안 써도 될 것 같은데, 이벤트 발생은 해서 조치가 필요한 상황
                - Information : 정보 메시지
                - debug : 디버그 메시지

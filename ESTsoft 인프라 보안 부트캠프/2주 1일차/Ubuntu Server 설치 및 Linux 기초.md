## Linux 배포판 및 인터페이스 특징

- 양대 산맥 배포판
    - **Debian 계열** : Debian(약간 상용), **Ubuntu**, Kali, BackTrack(오픈소스) 등이 있음. 데스크톱 GUI로 KDE를 사용함.
    - **RedHat 계열** : RedHat(상용), CentOS, Rocky, Fedora(오픈소스) 등이 있음. 데스크톱 GUI로 GNOME을 사용함.
    - **기타** : SuSe, Turbo, Oracle, Han Linux 등 무수한 오픈소스 Flavors가 존재함.
    - **참고 (UNIX)** : Oracle Solaris, HP, IBM은 상용(Commercial)이며, Free BSD는 오픈소스임.
- **인터페이스** : 키보드만 쓰는 CLI(CUI)와 마우스를 쓰는 GUI를 모두 사용함.

## 프린터 공유 설정 및 취약점

- **Samba 공유** : Linux는 프린터 설정이 까다로워 보통 Windows 머신에 드라이버를 깔고 **SMB/CIFS 프로토콜**을 지원하는 Samba 소프트웨어(smbd, nmbd 데몬 구동)를 통해 Linux와 공유해 사용함.
- **해킹 취약점** : Windows 머신이 Linux를 위해 Samba(특히 SMBv1)를 이용할 때 해킹을 수행할 수 있음. FBI가 개발 및 유출한 **EternalBlue(MS17-010)** 취약점 도구를 이용하면 선제적(ProActive) 조치로 대상 시스템의 권한을 탈취하고 정보를 추출할 수 있음.

## 서버와 클라이언트 개념 및 디스크 명칭

- **서버와 클라이언트** : 서버 패키지를 깔고 서비스를 켜면 서버가 되고 일반적으로 쓰면 클라이언트가 됨. 현재는 개념 구분이 모호하여 일반 설치 후 나중에 서버 서비스를 올려 사용할 수 있음.
- **하드디스크 명칭 (Windows vs Linux)** : Windows는 hdd0, hdd1 등으로 부르나 Linux는 sda, sdb 등으로 명칭함.
    - **파티션 인식** : sda는 첫 번째 HDD이며, 첫 파티션은 sda1, 두 번째 파티션은 sda2가 됨.
    - **외부 장치** : USB를 새로 끼우면 두 번째 장치이므로 sdb가 되고, 전체를 하나로 쓰면 sdb1이 됨.
    - **기타 장치** : DVD/CD-ROM은 **sr0**으로 인식함.
- **Windows 운영체제 체계** : Windows는 서버 OS(2008, 2016, 2022 등)와 클라이언트 OS(7, 11, 12 등)가 별도로 존재함.

## LVM 및 파티션·포맷 구조

- **LVM** (Logical Volume Management / 논리 볼륨 관리)
    
    물리 디스크의 경계를 허물고 공간을 유연하게 할당하는 핵심 기술임. 물리 디스크들에 분산된 유휴 공간들을 하나의 논리적 공간(Logical Volume)으로 묶어 데이터 변화에 따라 동적으로 병합 및 증설함.
    
- 운영체제별 디스크 장치 및 파티션 매핑
    - **첫 번째 하드디스크** : Linux 환경에서는 `/dev/sda`로 인식하며 파티션 분할 시 주 파티션 및 OS 설치 영역이 `/dev/sda1`, `/dev/sda2`로 나누어짐. 이는 Windows 환경의 **HDD0 (**`C:\`, `E:\` **등)**에 매핑됨.
    - **두 번째 하드디스크** : Linux 환경에서는 `/dev/sdb`로 인식하며 파티션 분할 시 `/dev/sdb1`, `/dev/sdb2`가 됨. 이는 Windows 환경의 **HDD1 (**`D:\`, `F:\` 등)에 매핑됨.
    - **광학 장치** : Linux 환경의 `/dev/sr0` 장치는 Windows 환경의 `G:\` **드라이브(DVD)**에 매핑됨.
- Partition과 Format의 정의
    - **Partition(파티션)** : 하나의 물리적인 하드디스크를 논리적으로 분할하여 **"데이터 저장 공간을 분할"**하는 행위임. (예 : 하나의 디스크를 프로그램 설치용 원형 데이터 영역과 일반 데이터 공간으로 분할)
    - **Format(포맷)** : 분할된 파티션에 파일 시스템을 구축하여 **"데이터 저장 준비를 시키는 과정"**임.
    - **실무 주의 사항** : 포맷 시 기존 인덱스 정보가 초기화되므로 일반적인 경로로는 기존 데이터 접근이 불가능함. 따라서 데이터 유실을 막기 위해 **포맷 전 사전 백업은 필수**적임.
- 포맷의 레벨별 분류
    - **Low Level Format (로우레벨 포맷)** : 물리적으로 디스크의 트랙과 섹터를 만드는 포맷임. 현대의 하드디스크 및 SSD 환경에서는 오직 제조사 공장에서만 수행 가능하므로 **Factory Format**이라고도 불림. 일반 사용자가 소프트웨어로 진행하는 것은 디스크 전체를 0으로 채우는 제로 필(Zero-Fill) 완전 삭제 가공 작업임. (레거시 환경의 CLI, DOS 계열 환경 구조(IO.SYS, MSDOS.SYS, AUTOEXEC.BAT) 등에서 물리 제어 개념으로 다루어짐)
    - **High Level Format (하이레벨 포맷)** : 공장 출하 및 로우레벨 포맷이 완료된 디스크 파티션 위에 윈도우의 NTFS나 리눅스의 ext4/xfs 같은 파일 시스템(개념적 격자 데이터 섹터 구조)을 생성하여 OS가 파일을 쓰고 읽을 수 있도록 소프트웨어 구조를 심는 일반적인 포맷 행위임.

## Linux 설치 후 필수 점검 파일 3가지 ★

<aside>
💡

- **/etc/hosts** : 도메인이 포함된 이름(FQDN)을 설정하며 서버 서비스 머신 지정 시 사용함.
    - *Windows 비교* : 사용자 계정 정보가 저장된 `C:\Windows\System32\config\SAM` 및 `SYSTEM` 파일과 `C:\Windows\System32\drivers\etc\hosts` 파일이 중요함.
- **/etc/network/interfaces** : Debian 계열에서 고정 IP 주소 등을 줄 때 사용함.
    - *RedHat 비교* : RedHat 계열은 `/etc/sysconfig/network-scripts/ifcfg-ens33` 형식의 파일을 열어야 함.
- **/etc/resolv.conf** : FQDN을 IP 주소로 이름풀이 해주는 DNS 서버 및 게이트웨이 설정 파일임. 리부팅 시 초기화될 수 있으므로 **resolvconf** 패키지 설정이 유용함.

## 파일 시스템 구조 및 절대경로·상대경로

- **루트 디렉터리** : 경로 맨 앞의 `/`는 최정상 [root] 디렉터리이며, 이러한 구조를 **POSIX(파직스)** 규격을 따르는 파일시스템 구조라고 함. 중간에 들어가는 `/`는 단순 구분자임.
    - *Windows 비교* : Windows DC 서버는 Active Directory structures(전화번호부 방식) 구조로 자료를 배열하고 Global Catalog에서 리소스를 찾는 방식으로 운영함.
- **경로 구분** : `/` 아래에는 home, bin, etc, tmp 등의 디렉터리가 있음. 최상위 `/`부터 시작해 적으면 **절대경로**, 현재 위치 기준으로 적으면 **상대경로**라고 함.

## 쉘 프롬프트와 커널의 이해

- **프롬프트 구조** : `ubuntu@ubuntu-1:~$` 형태로 나타남. (`~`는 현재 사용자의 홈 디렉터리인 `/home/ubuntu`를 의미함)
- **사용자 권한 구분** : 일반 사용자는 프롬프트에 `$`가 붙음. `sudo su root` 입력 시 관리자로 전환되며 홈 디렉터리가 `/root`인 root 사용자의 프롬프트 `#`으로 변경됨.
- **커널 조작** : 사용자는 쉘 프롬프트를 통해 커널(Kernel)을 조작함. **Bash Shell** 스크립트를 사용해 프로그래밍도 가능함. 정보보안/엔지니어 분야는 Python, Bash Shell script, Java script, C, PHP 정도를 이해해야 함.
- **하드웨어의 파일화** : Linux는 소프트웨어뿐 아니라 하드웨어도 파일로 취급함. "Linux는 Kernel이다"라고 표현함.
    - *초소형 운영체제* : 드론, IoT, 아두이노, 라즈베리 파이 등에 들어가는 임베디드 Linux는 GUI 없이 순수 커널로만 이뤄져 극단적으로 작은 크기로 구동됨.
    - *Windows 커널 비교* Windows의 최고 관리 권한은 Administrator보다 상위인 **SYSTEM** 권한이며, Linux는 root 권한보다 상위에 **Kernel**이 제어권을 가짐.
- **엔지니어 직무 지식** : Linux Server, Windows Server, Database(MySQL/MariaDB), PHP, Bash Shell Script, Network, Cloud, AI 지식의 틀을 제대로 잡아야 함.

## 네트워크 및 무선 해킹 지식

- **네트워크 상태 확인** : 콘솔에서 `ip add` 입력 시 루프백 주소와 DHCP로 자동 할당받은 네트워크 카드의 IP 주소가 보임.
- **자동 완성** : Linux, Windows 콘솔, 라우터/스위치 장비 콘솔에서 일부만 입력하고 **Tab 키**를 누르면 자동 완성됨.
- **브로드캐스트 구분** : 전체 네트워크에 다 뿌리는 일반 브로드캐스트는 `255.255.255.255`이고, 자신이 속한 특정 서브넷 대역 전체에 뿌리는 **디렉티드 브로드캐스트(Directed Broadcast)**는 `192.168.100.255` 형태로 지정함.
- **무선 해킹 장비 조건** : packet injection과 monitor mode가 가능하고, USB 타입의 2.4GHz와 5GHz dual band를 지원하는 IEEE 802.11a/b/g/n 장치를 구입하여 무선 인터넷 연결 키를 알아내는 무선 해킹 분석이 가능함.

## 주요 기본 명령어 명세 ★

- **sudo / su** : `sudo`는 일반 사용자가 관리자 권한을 쓰게 해 주며, `su`는 사용자 전환 명령어임.
- **pwd / cd / id**: 현재 작업 디렉터리를 보이고(`pwd`), 디렉터리를 이동하며(`cd`), 현재 사용자의 속성을 확인함(`id`).
- **Directory Traversal 취약점** : `ls ./`(현재), `ls ../`(하나 위), `ls ../../`(두 개 위) 방식으로 상위 디렉터리를 비정상적으로 조회하여 시스템 내부 파일에 접근하는 웹 취약점 공격 기법을 뜻함.
    - 네트워크 경로 기반 권한 상승(Privilege Escalation) 메커니즘
    - 침투 및 탐색 경로
        - 공격자(Attacker)가 외부망에서 방화벽(FW) 및 게이트웨이(GW)를 거쳐 내부망(LAN 환경)으로 진입하는 보안 침투 도식임.
        - 내부망 내의 타깃 장치(Notebook 또는 일반 권한 서비스 세션)에 최초 접근한 뒤, 시스템 내부에 존재하는 취약점(예: 앞서 배운 Directory Traversal 또는 Samba SMB 취약점 등)을 탐색함.
    - 권한 상승(Privilege Escalation)
        - 최초 침투 시 획득한 일반 사용자 권한을 기반으로 시스템 내부의 핵심 통제권인 **root 권한(Linux) 또는 SYSTEM 권한(Windows)**으로 침투 수위를 높이는 단계를 뜻함.
        - 최종적으로 서버 내부의 가장 깊숙한 핵심 제어권 영역(Root 커널/데이터베이스 저장소 공간)을 장악하여 원격 제어 및 정보를 유출하는 취약점 연쇄 공격 기법으로 이어짐.
- **cat / gedit / clear** : 텍스트로 내용을 보거나(`cat`), 그래픽 창으로 편집기를 열거나(`gedit`), 콘솔 창을 깨끗이 지움(`clear`).
- **ls / lsblk** : 현재 디렉터리 정보를 보며 주요 옵션으로 `a`(숨김 포함), `l`(속성 상세)이 있음. `lsblk`는 블록 장치의 구조를 트리 형태로 리스트함.
    - **블록 장치 확인**: 모든 블록 장치 파일은 `/dev/` 밑에 있으므로 `ls /dev/sd*`를 통해 sda, sda1, sdb 등을 확인함.
- **와일드카드 패턴 (Shell Globbing)** : `[a-z]`, `[A-Z]`, , `?` 등으로 문자·숫자를 대체함. 은 모든 문자열을 대체함.
- **mkdir / touch** : 디렉터리를 생성하고(`mkdir ABC`), 빈 파일을 생성하거나 타임스탬프를 변경함(`touch abc.lst`).
- 리다이렉션 기호 및 파이프
    - 좌측 표준 출력 결과를 우측 파일에 덮어씀 (덮어쓰기)
    - `>>` : 좌측 표준 출력 결과를 우측 파일 기존 내용 뒤에 이어서 추가함 (Append)
    - `<` : 우측 파일의 내용을 좌측 명령어의 표준 입력으로 밀어 넣음
    - `<<` : **Heredoc 기호**이며, 지정한 종료 문자열이 입력될 때까지 터미널 입력을 계속 받아 명령어로 전달함
    - `|` : 파이프 기호이며 좌측 명령의 표준 출력을 우측 명령의 표준 입력으로 전달하는 필터 역할을 함
- **cp / mv / rename** : 파일을 복사하고(`cp A B`, 속성 통째 유지는 `arp`), 이동하거나 이름을 바꿈(`mv`). 확장자 일괄 변경 시 `rename` 명령어를 사용함.
- **cat 활용 저장** : `cat > abc.txt` 입력 후 내용을 입력하고 `Ctrl + d` **(EOF 입력)**를 누르면 파일이 저장됨. `cat >> abc.txt`는 내용 추가임.
- **grep** : `grep "yes" abc.txt` 형태로 특정 문자열이 포함된 라인만 추출하며, `~ | grep` 형태로 파이프와 조합해 필터링에 자주 쓰임.
- **apt / dpkg (패키지 관리)** : Debian 계열에서 종속성 파일까지 일괄 설치하는 명령어는 `apt`이며 개별 데비안 패키지 파일은 `dpkg -i`로 설치함. 연산자 `&&`는 앞 명령 성공 시 뒤 명령을 실행하고, `;`는 성공 여부와 상관없이 순차 실행할 때 씀.
    - *RedHat 비교*: 일괄 설치는 `yum`(또는 `dnf`), 개별 설치는 `rpm -ivh`를 사용함.
- **find (고급 검색)** : 특정 조건으로 시스템 내 파일을 찾음.
    - *옵션 조건 예시*: `find /home -size +700M -mtime -1 -type d -user root -perm 777 -name "test.txt"` (크기가 700M 이상, 최근 24시간 이내 수정, 디렉터리 타입, 소유자 root, 권한 777, 파일명 일치 의미. `iname`은 대소문자 구분 없음. 확장자 지정 시 `.conf` 형태 사용)
    - *find 연동 실행*: `find ~ -exec 명령어 {} \;` 구조를 쓰면 검색된 결과가 `{}`에 매핑되어 명령이 연속 적용됨. 이때 `\;`는 -exec 옵션의 끝을 나타내는 약속된 기호이며, `\`는 세미콜론이 쉘에 의해 해석되지 않도록 막아주는 이스케이프(Escape) 문자임. (기타 이스케이프 문자: `\n` 개행, `\a` 벨소리, `\t` 탭 등)

## 파일 및 디렉터리 권한 상세 (**`chmod`**, **`chown`**)

- **권한 구조** : 대상은 User(소유자), Group(그룹), Other(기타)로 나뉘며 권한은 Read(4), Write(2), Execute(1)의 숫자 조합 또는 문자로 표기함. `+w -x` 식으로 특정 권한을 주거나 뺄 수 있음.
- **chmod 생략 규칙** : 대상 없이 `chmod +x abc.txt`라고 쓰면 `chmod a+x`와 같고, 이는 결국 `chmod u+x,g+x,o+x`와 동일하게 모든 대상에게 실행 권한을 부여함.
- **chown (소유권 변경)** : 파일·디렉터리의 소유자와 그룹을 `소유자:그룹` 형태로 변경함. 개별 변경도 가능함. 소유자는 모든 권한을 가지므로 root 관리자가 파일을 만들어 특정 사용자(ubuntu 등)에게 **권한 위임(privilege delegation)**을 하여 관리하게 할 때 주로 활용함.
- **ls -l 속성 상세 해석** : 맨 앞 글자로 종류를 나타내고 뒤이어 3자리씩 권한이 표시됨.
    - *종류 기호*: `d`(디렉터리), `l`(심볼릭 링크), (일반 파일), `s`(소켓), `c`(문자 장치파일)
    - *예시*: 일반 파일 권한이 `rw-r--r--`이면 각각 3자리씩 끊어 `6(rw-)`, `4(r--)`, `4(r--)`이 되므로 숫자 권한 **644**를 의미함.
- **숨김 파일** : 파일명 맨 앞에 `.`이 붙으면 숨김 파일이며 `ls -a`로만 조회가 가능함.

## 텍스트 조회 및 제어 추가 기능

- **more / less** : 긴 문장의 텍스트 파일을 읽을 때 화면/페이지 단위로 나누어 보여주며, 엔터나 스크롤바를 이용해 하단으로 내려가며 읽음.
- **rm -rf** : 특정 파일이나 디렉터리를 묻지 않고 하위 구조까지 강제로 완전 삭제하므로 실무에서 극도로 주의해야 함.
- **Ctrl + z** : 터미널에서 실행 중인 프로세스를 백그라운드로 일시 중지(Suspend)시킬 때 사용함. (완전 종료는 `Ctrl + c`)
- **주석처리 (#)** : 설정 파일이나 스크립트 안에서 `#`으로 시작하는 모든 줄은 주석(Remark) 문구로 인식되어 시스템 실행 대상에서 제외됨.
- **sed 편집기** : 스트림 편집기인 `sed`를 이용하면 파일을 직접 편집창으로 열지 않고도 원하는 라인의 텍스트를 효율적으로 검색, 치환, 삭제 및 제어할 수 있음.

## 서버 서비스 구동 명령어 (세대별 표준 문법)

네트워크 등 특정 서버 서비스를 시작할 때는 운영체제 개발 세대에 따라 아래와 같이 올바른 문법을 적용함.

- **최신형 머신 (systemd 기반 표준)** : `systemctl start networking` (또는 `systemctl start NetworkManager`)
- **약간 이전 머신 (SysV init 호환)** : `service networking start`
- **아주 오래된 머신 (Legacy 스크립트 직접 실행)** : `/etc/init.d/networking start`

## 가상화 구축 필수 전제 조건 (BIOS 및 가상화 설정)

- **하드웨어 가상화 활성화 :** 가상화를 하기 위해 호스트(노트북/데스크톱) 부팅 시 **BIOS 설정 화면**으로 진입해야 함. CPU 설정 메뉴에서 **'가상화 지원(Intel VT-x / AMD-V)'** 항목을 찾아 체크(Enabled)해야 함.
- **VMware 내부 가상화 설정 :** VMware 설치 후 Windows Server 2016 VM을 생성·설치할 때, 프로세서(CPU) 옵션에서 **'Virtualize Intel VT-x/EPT or AMD-V/RVI'** 항목에 체크해 주어야 가상 머신 내부에서 하이퍼바이저(Hyper-V) 기능을 정상적으로 쓸 수 있음.
- **중첩 가상화(Hyper-V) 우회 설정 (.vmx 수정) :** Windows Server 2016 VM이 VMware 위에서 동작하는 구조이므로, 호스트(Windows 10)에서 우회 작업이 필요함.
    1. 메모장을 **'관리자 권한으로 실행'**으로 열기함.
    2. VM 설치 경로(`D:\VMware\WINSER_2016\`)로 이동하여 파일 형식을 '모든 파일(*.*)'로 변경함.
    3. 실제 VM 실행 설정 파일인 **`WINSER_2016.vmx`** 파일을 더블클릭하여 열기함.
    4. 파일 맨 아래에 **`hypervisor.cpuid.v0 = "FALSE"`** 구문을 추가하여 부모 하이퍼바이저의 존재를 자식 OS에게 숨겨 가상화 기능을 정상 작동하도록 설정 후 저장하고 닫음.

## 가상화 기술 및 현장 실제 VMware 적용 방법 ★

- **Hyper-V의 개념:** Linux의 KVM과 유사한 Windows Server 2016의 자체 하이퍼바이저 서비스임. 가상 컴퓨터(VM) 및 해당 리소스를 생성·관리하고 하나의 시스템에 여러 OS를 독립적으로 설치·구동하는 도구임.
- **현장 실무 인프라 구축 패턴:** 현업 환경에서는 두 가지 방식으로 고성능 물리 호스트를 활용함. ★
    - **방식 A :** 매우 성능이 좋은 싱글 호스트에 **VMware 하이퍼바이저를 올리고 그 위에 수많은 가상 머신(VM)을 집중 설치**하여 운영함.
    - **방식 B :** 성능이 좋은 호스트에 Windows Server 2016을 설치한 뒤, 자체 기능인 **Hyper-V를 활성화하여 다수의 VM을 생성**하고 관리함.
- **가상화 네트워크의 난이도 :** 가상 머신을 생성한 이후 인프라 세팅에서 **가상 네트워크(Virtual Network) 설정** 부분이 가장 까다롭고 정교한 작업이 요구됨.
- **가상화 기술의 미래 트렌드 :** 현재는 VMware와 Citrix 소프트웨어가 시장을 주도하고 있으나, 조만간 **Docker Image와 Kubernetes(컨테이너 오케스트레이션)** 기반으로 이동할 예정임. 엔지니어에게는 단순 실습보다 이러한 '개념과 처리 과정'을 이해하는 논리적(Logical)이고 합리적(Reasonable)인 사고가 훨씬 중요함. ★

## 데이터 처리 및 인프라의 미래 (128비트 & IPv6)

- **네트워크 주소 전환 :** 현재는 IPv4와 IPv6가 공존하는 **Dual Stack(듀얼 스택)** 구조를 사용하지만 차후에는 IPv6로 전면 전환됨.
- **128비트 변혁 :** 128비트 기반 데이터 전송은 표현 주소 공간과 데이터 처리 용량이 크게 확장됨. 하드웨어와 소프트웨어 모두 128비트 데이터 처리 시스템으로 전면 전환되어야 하므로 IT 업계 전반에 거대한 변혁이 올 수 있음.

## PowerShell을 활용한 전문 서버 관리

- **개념 및 위상 :** Windows Server 2008/2016 및 Windows 7부터 도입됨. Linux의 Bash Shell Script처럼 쉘 명령어로 Windows를 전문 관리하는 강력한 스크립트 언어 도구임.
- **호환성 및 인터페이스 :** 기존 DOS 명령어와 VBScript 명령을 그대로 사용할 수 있음. 'PowerShell Premium' 환경이라 할 수 있는 'PowerShell ISE (x86)'를 실행하면 3개의 분할 창이 나타남. 첫 번째 창은 쉘 스크립트 입력 공간, 세 번째 창은 CMD 스타일 명령어 입력 공간이며, 양쪽의 실행 결과가 가운데 창에 통합되어 출력됨.
- **구문 및 명령어(Cmdlet) 특징 :**
    - 내장 명령어를 **Cmdlet**이라고 부르며, 명령어 외에도 Cmdlet을 쉽게 호출하는 Alias(별칭)와 사용자 정의 Function(함수) 기능도 내장됨.
    - 명령어 입력 시 대소문자를 구분하지 않음.
- **주요 명령어 활용법 :**
    - **`get-command | more`:** 전체 명령어 목록을 가져와 파이프(`|`, vertical bar)를 통해 우측 명령어로 넘긴 뒤, `more`를 통해 긴 출력을 페이지 단위로 잘라서 보여줌.
    - **경로 제어:** `./`는 현재 위치, `../`는 상위 위치를 뜻함. (예: `/home/centos`에서 `cd ../` 하면 `/home`으로 이동, `cd ../../` 하면 최상위 루트 `/` 로 이동함).
    - **시스템 제어 :** PowerShell 환경에서 스크립트를 작성하여 방화벽 규칙 변경, IP 주소 할당, DNS 서버 지정 등 네트워크 핵심 설정을 일괄 제어할 수 있음. .NET 프로그래밍 및 Visual Basic 프로그래밍 지식이 있으면 VBScript와 연계하여 확장성이 극대화됨.
- **개발 언어 비교 트렌드 :** 국내 표준은 Java(다소 무거움, 웹은 JSP/JavaScript 활용) 중심이지만, 국제적으로는 가볍고 함수가 많은 PHP가 널리 쓰임. 일본 등에서는 MS에서 만든 Visual Basic 도구를 .NET Framework와 함께 널리 사용하고 있음.

## 서버 서비스 운영 프로세스 (기본 6단계)

서버 호스트가 정상적으로 서비스를 제공하기 위해 거쳐야 하는 필수 프로세스임.

- 순서
    1. **설치 (Installation) :** 해당 서비스 프로그램 설치함.
    2. **구성 (Configuration) :** 세부 환경 설정함.
    3. **실행 (Execution) :** 서비스 프로세스 구동함.
    4. **방화벽 허용 (Firewall Open) :** 해당 서비스의 통신 포트 개방함.
    5. **확인 (Verification) :** `netstat` 등의 명령어로 서비스 상태 및 포트 활성화 체크함.
    6. **클라이언트 접속 :** 외부 사용자 유입 및 서비스 시작함.

## IIS(Internet Information Service) 웹 서버 실습 및 운영 ★

- **IIS 서비스의 본질 :** Windows Server에 IIS를 설치하면 **웹 서버(HTTP)** 서비스가 생성되며, 별도 선택에 따라 **파일 서버(FTP)** 서비스를 함께 추가할 수 있음.
- **플랫폼별 웹 서버 및 스크립트 비교**
    - **Windows Server:** IIS 기반으로 구동되며, 서버측 스크립트로 **ASP** 프로그래밍 언어를 사용할 수 있음.
    - **Linux (CentOS/Rocky):** Apache 서버 기반으로 구동되며, 서버측 스크립트로 **JSP** 언어를 사용할 수 있음.
- **웹 홈피 포맷 및 디렉터리 경로 :** 웹 서버에 접근했을 때 첫 페이지는 반드시 웹 구동 포맷(`index.html`, `index.php` 등)으로 구성되어야 함. OS별 기본 웹 루트 경로는 아래와 같음.
    - **Windows (IIS) :** `C:\inetpub\wwwroot\` 디렉터리 내에 `index.html` (또는 htm) 파일이 존재해야 함.
    - **Linux (Apache) :** `/var/www/html\` 디렉터리 내에 `index.html` 파일이 존재해야 함.
- **기본 문서(Default Document) 우선순위 제어 :** IIS 관리자 설정 내 **'기본 문서'** 항목으로 진입하면 여러 개의 index.html 파일 목록이 보임. 우측 컨트롤러를 이용해 이 파일들의 상하 위치(우선순위)를 조절할 수 있음. 외부 사용자가 IIS 웹 서버로 접속할 때 가장 상단에 배치된 웹 페이지가 기본 출력됨. 이를 활용해 봄, 여름, 가을, 겨울용 홈페이지를 미리 생성해 두고 계절마다 상하 위치만 변경하는 방식으로 유연하게 웹 서비스를 운영할 수 있음.
- **웹 디렉터리 경로 변경을 통한 랜섬웨어 방어 :** 해커들이 조직의 웹 서버를 타깃으로 삼을 때, 기본 경로(`C:\inetpub\wwwroot` 또는 `/var/www/html`)를 기본적으로 탐색하여 파일을 암호화함. 따라서 조직의 중요한 홈페이지는 디폴트 위치가 아닌 **다른 임의의 경로에 저장해 두고 IIS 설정에서 경로를 지정**하여 운영하는 것이 공격 노출을 줄이는 데 유용함.

## 인프라 보안 및 네트워크 취약점 방어 전략

- **최소 설치의 원칙 :** 서버에 PDF, PowerShell, PHP, MS SQL 등 불필요한 프로그램이 많이 깔려 있으면, 해당 소프트웨어의 취약점을 타고 들어와 OS 자체에 접속하고 데이터를 유출할 수 있음. 서버에는 언제나 **최소한의 서비스 프로그램만 설치**하고 필요한 것은 그때그때 추가해야 함. 필요 시 CDN(콘텐츠 전송 네트워크)이나 Edge 네트워크 구조를 도입하는 것이 좋음.
- **Zero Trust & Zero Day Attack :** 취약점이 발견되자마자 즉시 공격이 들어오는 '제로 데이 공격'이 만연함. 이에 따라 취약점을 발견한 해커의 즉각적인 공격을 방어하기 위해 시스템을 일시 폐쇄하거나, 기존에 설정해 두고 안전하다고 확신했던 인프라 요소까지 끊임없이 재검증하는 **'Zero Trust(아무도 믿지 않는다)'** 보안 모델을 항상 염두에 두어야 함.
- **하드웨어 및 소프트웨어 암호화 :** 마더보드에 **TPM(Trusted Platform Module)** 보안 칩셋 장착 시, 장치 내부에 저장된 키 정보가 없으면 HDD 등 저장 장치를 물리적으로 떼어가도 데이터를 열 수 없음. 이를 OS단에서 소프트웨어적으로 구현한 기능이 Windows의 **BitLocker**임.
- **방화벽 처리 (Permit / Drop / Reject) :** 외부에서 내부로 유입되는 패킷을 판단하는 차단 설정임. `Permit`은 통과, `Drop`은 로그 기록 여부와 무관하게 거부 통보 없이 패킷을 버림, `Reject`는 거부 통보를 발송하며 패킷을 버림. (Linux는 iptables, firewall-cmd 등으로 통제하며 Windows는 제어판 방화벽에서 설정함). 관련하여 IDS/IPS(snort, suricata), VirusWall, NID, HID 솔루션이 있음.
- **네트워크 스니핑과 무차별 모드 :** NIC(네트워크 카드)를 **Promiscuous mode(무차별 모드)**로 전환하면 자신과 상관없는 네트워크의 모든 패킷을 모니터링하고 가로챌 수 있음. 본래 네트워크 모니터링 및 대역폭 산정을 위해 고안되었으나 악용 위험이 큼. 이 모드가 활성화된 호스트는 비정상적인 데이터 탐색 행위가 증가하므로, 보안 관리자(AI Agent)가 이를 실시간 체크하여 차단할 수 있음.
- **웹 프록시 변조 공격 :** 클라이언트와 서버 사이에서 오가는 데이터를 중간에 멈춰 세운 뒤, 내용을 강제로 변조하여 전송하는 해킹 도구로 **BurpSuite**나 **Paros** 등이 존재함.

**IDS와 IPS**

예전에 정보보안 공부할 때 침임탐지, 방지로 공부했던 것 같은데, 다시 짚고 넘어가야겠다.

| **구분** | **IDS (침입 탐지 시스템)** | **IPS (침입 차단 시스템)** |
| --- | --- | --- |
| **주요 역할** | 이상 패킷의 **탐지 및 경고 (Passive)** | 이상 패킷의 **탐지 + 실시간 차단 (Active)** |
| **연동 방식** | **Mirroring (인라인 외부 배치)** | **In-Line (네트워크 통로 중간 배치)** |
| **네트워크 영향** | 장비 장애 시에도 서비스에 영향 없음 | 장비 장애나 부하 발생 시 **인프라 전체 마비 가능** |
| **실무적 위상** | CCTV (사후 증적 및 모니터링) | 무인 경비원 (실시간 물리적 제어) |

IDS는 포트 미러링으로 패킷의 복사본을 분석하는 것이라 IDS에 문제 생겨도 괜찮음. 하지만 IPS는 실제 네트워크에 끼워넣기 때문에, IPS에 문제 생기면 망하는것임…

</aside>

**해시함수의 해독과정**

내 기억이 맞다면 해시함수는 일방향성을 띄어서 해독이 불가능했던 것 같은데, 강사님이 웹 상에 존재하는 사이트에 해시값을 입력하는 것 만으로 해독이 됐다.. 이후 서버의 한 명령어 사용으로도 해독이 되었으나, 그것은 명령어에 함께 사용된 문서파일 내부의 값들을 하나 하나 해시값을 구해서 대조해본게 아닐까 싶었다. 하지만 해시함수로 구한 값의 어떤 부분을 썼는지 어떻게 알고? 라는 생각이 들어, 해시함수의 해독과정이 궁금해졌다.

공부를 하다 만 것일까.. 레인보우 테이블 공격이 있었다. 맞다, 있었다. 이외에도 브루스 포스 공격이라고 모든 문자열을 집어 넣어보는 비효율적이지만 확실한 공격도 있었다. 그리고 사전에 사람들이 자주 사용하는 암호 같은 것들을 모아놓은 딕셔너리 데이터베이스를 이용하는 공격도 있었다. 내가 다른 암호화와 헷갈린 것 같은데, 해시함수는 일정 부분을 사용하지 않는다. 데이터를 블록으로 나누어 패딩까지 해 해싱 준비를 마치고, 비트 연산과 비트 시프트로 역연산이 불가능하게 만드는 것이었다. 그렇기에 사전 공격이나 레인보우 테이블이 취약점으로 작용하는 것이었다…. 😩  

</aside>

**IaC**

예전 클라우드를 공부하면서 IaaS, PaaS, SaaS랑 같이 봤던 기억이 어렴풋이 나서 다시 찾아봤다.

얘는 쉽게 말해 우리가 장비를 물리적으로 연결하거나 하는 행동을 코드로 하는 것임. 실제 물리적 장비가 아닌, 오늘 배운 가상머신의 경우라면 스위치같은 장비들도 분명히 있고, 이러한 자원들을 명령어로 셋팅하는 것임. 엄청남.

클라우드랑 같이 떠오른 기억이었던 이유는 온 프레미스 시장이 작아지고 클라우드 시장이 커지면서 자연스럽게 하드웨어도 클라우드 내의 가상머신으로 변하게 됨. 이에 따라 IaC도 함께 각광받게 되어 함께 기억하게 된 것이었음.

</aside>

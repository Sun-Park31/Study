## 로컬 네트워크(LAN) 내 전송 및 ARP 메커니즘

- **MAC 주소 기반 통신**: LAN 환경에서 각 노드는 IP 주소를 알고 있더라도, 실제 L2 계층의 데이터 전달을 위해서는 상대방의 물리적 주소인 **MAC 주소**를 인식해야 함.
- **ARP 프로토콜 동작 (1번 노드가 4번 노드를 찾을 때)**:
    - **질의 (Broadcast)**: 1번 노드가 로컬 LAN 전체에 ARP 브로드캐스트 패킷을 살포함. 타 노드들은 자신에게 온 패킷이 아니므로 무시(Ignore)함.
    - **응답 (Unicast)**: 오직 4번 노드만 이를 인지하고 자신의 MAC 주소를 담아 1번 노드에게 유니캐스트로 답변을 보냄. (LAN 내 대상 탐색은 브로드캐스트, 응답은 유니캐스트 방식)
    - **ARP 캐시 테이블 저장**: 획득한 주소는 시스템 내 **ARP 캐시 테이블(**`arp -a`)에 저장되며, 일정 시간이 지나면 네트워크 효율성을 위해 자동 삭제(Aging)됨. 네트워크상에 떠도는 불필요한 패킷 찌꺼기들은 'Debris'라고 부름.
- **Promiscuous Mode (무차별 모드)**: 네트워크 카드(NIC)를 무차별 모드로 설정하면(Kali Linux 등), 목적지가 자신이 아닌 타 노드 간의 패킷까지 무조건 수신하여 가로챌 수 있음.

## 외부 네트워크(WAN) 전송 및 라우터 패킷 처리

- **게이트웨이(Gateway) 전달**: 1번 노드가 외부 WAN 사이트(`://naver.com`)에 연결하고자 할 때, 로컬 LAN에 목적지가 없으므로 패킷을 라우터의 **게이트웨이** 주소로 던지고 처리를 위임함.
- **라우팅 프로토콜 및 테이블 운영**:
    - 라우터는 패킷의 목적지 IP 주소 중 **네트워크 주소(Network Address)** 영역을 확인하여 패킷을 최적의 경로로 포워딩함.
    - 거리 벡터 라우팅 프로토콜인 **RIP (v2)**는 라우팅 루프를 방지하기 위해 최대 **15 홉(Hop/Metric)**까지만 경로 인식이 가능하며, 16 홉은 통신 불가(Unreachable)로 판단함.
    - 라우터는 수집한 경로 정보를 **라우팅 테이블(Routing Table)**에 기록하여 메모리에 유지함. (판서에 언급된 CAM 메모리는 라우터보다는 스위치가 MAC 주소 테이블을 매칭할 때 하드웨어적으로 초고속 검색을 하기 위해 사용하는 영역임.)
    - **패킷 수명 (TTL : Time To Live)**: 패킷이 라우터를 거칠 때마다 L3 헤더의 **TTL** 값이 1씩 감소하며, 네트워크 루프 상태 등으로 인해 TTL이 0이 되면 해당 패킷은 즉시 **버려짐(Discard)**.
- **IP 주소 및 패킷 구조**:
    - 패킷은 제어 정보를 담은 `Header`와 실제 전송할 `Data`가 결합됨.
    - Class C 주소인 `192.168.100.123 /24 (255.255.255.0)` 환경에서 네트워크 주소는 `192.168.100.0`이며, 해당 네트워크의 브로드캐스트 주소는 `192.168.100.255`가 됨.

## 현대 비밀번호 보안 트렌드 (NIST SP 800-63B 가이드라인)

- 트렌드
    - **길이 중심 보안(Length beats Complexity)**: 대/소문자, 숫자, 특수문자를 조합하라는 복잡성 규칙은 최신 NIST 가이드라인(SP 800-63B)에서 **공식적으로 폐기 및 금지**됨. 짧고 복잡한 암호보다 무작위 단어 조합인 **패스프레이즈(Passphrase)**가 엔트로피 측면에서 훨씬 안전함.
    - **패스워드 엔트로피 계산**: 엔트로피 수식은 \(H = L \times \log_2(N)\) 임. 문자 유형을 늘려 N(문자셋 크기)을 조금 늘리는 것보다, **글자 수 L(길이)을 늘려 검색 공간을 기하급수적으로 확장하는 것이 크랙 방지에 훨씬 유리**함.
    - **최신 NIST 권장 기준(Rev. 4)**: 단일 인증 요소를 사용할 경우 **최소 15자 이상**의 길이를 강력히 권장하며, 시스템은 공백과 특수문자를 포함하여 **최소 64자 이상**의 긴 암호를 입력할 수 있도록 지원해야 함. 주기적인 강제 패스워드 변경 정책은 폐지됨.
    - **공격자의 크랙 기법**: (1) 데이터 브리치 덤프를 이용한 자격 증명 스터핑(Credential Stuffing), (2) 사전 파일에 기반한 변형 공격(Leet 치환, 숫자 접미사 추가), (3) 키보드 패턴 매칭, (4) 마르코프 체인 모델, (5) 마지막 순위로 순수 무작위 대입(Brute Force) 순으로 진행됨.
    - **해시 함수 연산 속도**: MD5는 고성능 GPU 연산 시 초당 수천억 번의 대입이 가능해 매우 취약하나, 솔트(Salt)와 반복 연산 비용(Cost factor)을 적용한 **bcrypt**나 **Argon2** 방식을 사용하면 연산 속도가 급격히 조절되어 오프라인 크랙 속도를 비약적으로 지연시킴.
    - **안전한 패스워드 확인(k-Anonymity)**: Password Meter 검증 도구는 Have I Been Pwned(HIBP) 연동 시 익명성 보장을 위해 **k-Anonymity 범위 API**를 활용함. 입력된 패스워드의 전체 평문이나 전체 SHA-1 해시를 절대 외부로 보내지 않고, **해시의 앞 5자리 접두사(20비트)**만 전송한 뒤 서버로부터 리턴받은 접미사 후보 목록을 사용자 브라우저(클라이언트) 내부에서 매칭하여 안전하게 확인함.

## 자동화 이메일/SMS 워크플로우 테스팅 (Mailinator 서비스)

- **테스팅 자동화**: 가입 인증, 비밀번호 재설정 링크, 2FA/OTP 검증을 위해 Selenium, Cypress, Playwright 등의 자동화 도구 및 CLI, API와 연동해 실시간 메시지 유효성을 검증함.
- **동적 인박스(Inbox)**: 사전에 메일 주소를 생성하지 않더라도 해당 도메인으로 메일이 수신되는 순간 실시간으로 인박스가 즉시 활성화되는 구조임.

## Kali Linux 및 가상화 아키텍처

- **가상머신 규격**: VMware, VirtualBox, Hyper-V, QEMU 등 가상화 환경에 최적화된 Pre-built 배포판을 제공하며, 최초 구동 시 **기본 사용자 이름과 패스워드는** `kali / kali`임.
- **다양한 아키텍처 지원**: PC용 설치 이미지 외에도 라즈베리 파이 등의 단일 보드 컴퓨터(ARM), 모바일 펜테스팅 플랫폼인 **Kali NetHunter** 환경을 제공함. NetHunter Pro(PinePhone용 등)의 시스템 **기본 자격 증명은** `kali / 1234`를 사용함.
- **무선 인젝션 및 모바일 공격 지원**: NetHunter 전용 커널은 무선 패킷 주입(802.11 Wireless Injection)을 완벽히 지원하며, 타겟 PC에 연결하여 악성 키보드로 작동하게 하는 USB HID 공격(Teensy 모방)이나 BadUSB MITM 공격을 지원함.

## DNS 캐시 포이즈닝 메커니즘 (CVE-2008-1447 공격 코드)

- **취약점 정보(CVE)**: 2008년 댄 카민스키(Dan Kaminsky)가 발표한 전 세계적인 DNS Insufficient Socket Entropy 취약점(DNS 캐시 포이즈닝)의 공식 식별 번호는 **CVE-2008-1447**임.
- **Exploit 6130 C 소스코드 동작 단계**:
    1. **무작위 질의 생성**: 공격자는 타겟 DNS 리졸버에 존재하지 않는 무작위 호스트네임(예: `[임의의랜덤값].example.com`)을 만들어 질의 패킷(`build_query`)을 대량으로 보냄.
    2. **조회 유도**: 타겟 리졸버는 자신의 캐시에 정보가 없으므로 해당 도메인의 상위 권한 네임서버(Authoritative Server)로 질의를 전달하고 답변을 기다리는 상태가 됨.
    3. **가짜 응답 주입(Spoofing)**: 공격자는 리졸버가 대기하는 찰나의 순간에 상위 권한 네임서버의 소스 IP를 사칭하여 위조된 DNS 응답 패킷(`build_response`)을 대량으로 주입함. 이때 리졸버가 요구하는 16비트의 트랜잭션 ID(TXID)와 UDP 소스 포트 번호가 일치하면 가짜 응답이 진짜로 승인됨.
    4. **캐시 오염의 핵심**: 공격자는 단순 가짜 IP(A 레코드) 답변만 주는 것이 아니라, 응답 패킷의 **권한 섹션(Authoritative Section)**에 공격자가 장악한 가짜 네임서버 도메인(`subhost.domain`)을 **NS(Name Server) 레코드**로 등록하고, **추가 섹션(Additional Section)**에 그 가짜 서버의 실제 IP 주소를 A 레코드로 강제 주입함. 이로 인해 해당 도메인 하위의 모든 질의가 해커의 가짜 서버로 강제 리다이렉트되도록 캐시가 완벽히 오염됨.

## 표준 모의해킹(PenTester) 실습 프로세스

1. **타겟 정보 수집 (Nmap 스캔)**: `nmap -A [타겟IP]` 명령어를 수행하여 오픈된 포트 정보와 실행 중인 서비스 명, 정확한 소프트웨어 버전을 파악함. 필요시 *Metasploit, NSE(Nmap Script Engine), SET(Social Engineering Toolkit)* 등 공격 모듈 도구 모음을 활용함.
2. **취약점 분석 및 CVE 매핑**: 스캔 결과를 통해 특정 서비스 버전(예: BIND 9.4.2)을 확인하면 알려진 취약점을 추적하여 `CVE-2008-1447` 취약점을 식별해 냄.
3. **공격 코드(Exploit) 확보**: 취약점 데이터베이스 아카이브 사이트인 **익스플로잇 DB(**`://exploit-db.com`)에 접속하여, 해당 CVE에 대응하는 검증된 공격 소스 코드를 확보한 후 파일로 저장하고 실행 권한을 부여함.
4. **보안 장비 우회 및 AV 테스트**: 확보한 공격 코드를 **바이러스토탈(**`Virustotal.com`)에 업로드하여 타겟 시스템의 안티바이러스(AV)나 방화벽(FW) 장비에 탐지되는지 사전 검증하고 필요시 우회 기법을 적용함.
5. **침투 및 취약점 리포트 작성**: 우회된 코드로 타겟에 최종 침투하여 자격 증명이나 내부 기밀 데이터를 추출함. 최종적으로는 *Nessus*나 *OpenVAS* 같은 전문 취약점 진단 스캐너를 구동하여 취약점 리포트를 발행하고 방어 대책을 마련함.

## 시스템 보안 및 서버 운영 환경 요약

- **획득 가능한 쉘의 종류**: 공격자가 타겟의 인바운드 방화벽 포트를 뚫고 들어가는 **Bind-Shell**과 타겟이 아웃바운드로 공격자에게 연결을 수립하여 외부 방화벽 정책을 우회하는 **Reverse-Shell**로 나넒.
- **하트블리드(Heartbleed)**: OpenSSL의 구조적 취약점(Heartbeat 확장 기능 오류)을 악용하여, 정상 암호화 통신을 처리하는 서버 메모리 내부에 상주하는 암호화 비밀키와 세션 쿠키, 개인정보를 무단으로 추출하는 공격임.
- **와이어샤크(Wireshark) 암호화 스트림**: 데이터가 정상적으로 암호화(SSL/TLS)된 상태라면 패킷을 덤프하여 `Follow TCP Stream`을 실행하더라도 데이터가 전부 깨진 난수로 표시되어 본문을 읽을 수 없음.
- **텍스트 기반 웹 서버 제어 (curl)**: GUI 화면이나 웹 브라우저가 없는 Linux 도커 환경 등에서는 웹 서비스의 동작 여부를 진단하기 위해 텍스트 기반 명령어인 `curl` 형식을 사용하여 정상 코드 출력을 확인함.
- **리눅스 권한 관리**: 일반 사용자가 `sudo su root` 등을 활용하여 관리자 권한을 빌려 쓸 때 계정 패스워드를 요구함. 최초 인증 성공 시 **5분 동안**은 패스워드 입력 없이 관리자 명령 수행 권한이 캐싱됨.
- **웹 서버와 WAS의 차이점**: 정적 텍스트 및 이미지 전달에 특화된 **Apache**와 내부 자바(Java) 모듈 및 웹 애플리케이션 코드를 구동하는 웹 애플리케이션 서버(WAS)인 **Apache Tomcat**으로 명확히 분류됨.

## 대칭키 vs 비대칭키 작동 메커니즘

- **대칭키 암호화 흐름**
    - **메커니즘**: 송신자 A(Rocky)가 평문장에 암호화 키를 적용하여 암호문을 생성한 후 수신자 B(Ubuntu)에게 전송함.
    - **복호화**: 수신자 B는 전달받은 암호문에 송신자와 **동일한 키**를 적용하여 다시 평문장으로 되돌려 읽음.
    - **특징**: 암호화와 복호화에 하나의 키만 사용되므로 **단일키/공유키**라고 불림.
- **비대칭키 암호화 및 상호 인증 흐름**
    - **키 쌍 생성 (Pair)**: 클라이언트 **Ubuntu**가 자신의 머신에서 개인키와 공개키를 한 쌍으로 동시에 생성함.
    - **공개키 전달**: Ubuntu가 서버 **Rocky**에게 공개키를 전달하여 등록시킴. (Rocky 서버에는 수많은 클라이언트의 공개키가 저장됨)
    - **인증 및 접속**: 클라이언트(Ubuntu)가 자신의 **개인키**로 서버(Rocky)에 접속을 시도하면, 서버에 저장된 **해당 클라이언트의 공개키**가 이를 검증 및 상호 인증(`mutual authentication`)하여 연결을 승인함.

## 암호학 및 데이터 통신 기초 개념

- **데이터 표현 및 네트워크 경로**
    - **ASCII vs Binary**: 인간이 인식하는 키보드 문자 데이터(ASCII)는 전송 시 컴퓨터가 이해할 수 있는 2진수 데이터(Binary)로 변환되어 처리됨.
    - **절대 경로 vs 상대 경로**: 리눅스 환경에서 최상위 루트 기호(`/`)로 시작하면 절대 경로, 현재 위치(`.` 또는 `..`)를 기준으로 이동하면 상대 경로임.
    - **Heartbeat (하트비트)**: 두 노드가 지정된 시간(15초, 30초 등)마다 `Hi00...00` (32비트) 구조의 **Hello Packet**을 주고받으며 연결 상태를 점검함. 지정 시간 내 응답이 없으면 백업 장치 전환이나 경로 재탐색, 테이블 정보 삭제가 일어남.
- **암호화 및 해시 알고리즘 분류**
    - **블록 암호화와 파이스텔(Feistel) 구조**: 특정 계산 함수를 여러 회차(Round) 반복하여 암호화하는 구조임. `(3)DES`, `Blowfish`, `SEED` 등이 이 구조를 따름.
    - **대칭키 알고리즘**: DES, 3DES, AES, SEED, ARIA, IDEA, RC5, Skipjack, Serpent, Twofish
        - *한계 및 예시*: 암호문과 키를 함께 전달해야 하므로 배송 중 탈취 위험이 있음. 예를 들어 평문 `iloveyou.`를 키 값 `3`과 철자 이동 알고리즘으로 암호화하여 `filsbvlr.`로 보낼 때, 키 `3`이 함께 전송되므로 위험이 존재함.
    - **비대칭키 알고리즘**: DSA, RSA
        - *특징 및 예시*: 개인키 생성 시 매우 큰 두 개의 **소수(Prime Number)**를 결합하여 만들어 보안성이 매우 높음.
        - *수학적 검증 예시*: 초기 데이터 `4`에 대해 송신자 키 `2`, 수신자 키 `3`을 개인키로 가짐. 송신자가 `4^2 = 16`을 보내고, 수신자가 `4^3 = 64`를 보낸 뒤, 교차하여 상대방의 결과값에 다시 제곱 연산(\(64^{2}\) 및 \(16^{3}\))을 하면 양측 모두 최종적으로 `4096`이라는 동일한 값에 도달함. 송수신자가 각자의 **개인키(2와 3)**로 연산한 결과가 웹 등에 공개된 검증 값(`4096`)과 일치하면 데이터와 송수신자를 신뢰하게 되는 구조임.
    - **해시(Hash) 알고리즘**: MD5, SHA1, SHA512 (데이터 무결성 검증용)

## SSH (Secure Shell) 키 기반 보안 구축 실습

- **무차별 대입 공격(Brute Force) 방어**
    - ID와 비밀번호를 기반으로 로그인(Credential 인증) 체제를 사용하면, 공격자가 사전 파일(Dictionary File)을 활용해 Hydra나 Medusa 같은 도구로 계정을 크랙할 수 있음.
    - 이를 방어하기 위해 아이디/패스워드 로그인을 금지하고 **비대칭키 기반 인증**을 강제하면 무차별 대입 공격을 원천 차단할 수 있음.
- **SSH 키 기반 인증 구축 단계**
    1. **클라이언트 키 생성**: Ubuntu, CentOS, Windows 10 등의 클라이언트 머신에서 각각 개인키/공개키 쌍을 생성함.
    2. **서버에 공개키 등록**: 각 클라이언트의 공개키 내용을 Rocky SSH 서버의 `/home/rocky/.ssh/authorized_keys` 파일 내에 추가 저장함.
    3. **서버 로그인 정책 변경**: 서버의 SSH 설정 파일인 `/etc/ssh/sshd_config`를 수정하여 오직 키 인증만 허용함.
        - `PubkeyAuthentication yes` (48번 라인: 공개키 인증 활성화)
        - `PasswordAuthentication no` (70번 라인: 패스워드 인증 비활성화)
- **실습 관련 주요 명령어**
    - **서버 SSH 서비스 활성화**: `/etc/init.d/ssh start`
    - **방화벽 포트 허용 (22번)**: `ufw allow 22/tcp`
    - **서비스 포트 구동 확인**: `netstat -nltp | grep 22`
    - **Hydra/Medusa를 이용한 텔넷(Telnet) 크래덴셜 크랙 실습**:
        - *Hydra*: `hydra -L Desktop/user.txt -P Desktop/passwd.txt 192.168.100.143 telnet -t 4`
        - *Medusa*: `medusa -h 192.168.100.143 -U Desktop/user.txt -P Desktop/passwd.txt -M telnet -t 4`
    - **SCP를 이용한 암호화 파일 송수신**:
        - *보내기*: `scp [내파일] rocky@192.168.100.201:/home/rocky/Desktop/`
        - *가져오기*: `scp root@192.168.100.201:/home/rocky/sym_key.txt.gpg /home/ubuntu/Desktop/`
    - **SELinux 보안 완화 (Rocky Linux)**: `setenforce 0` (임시 해제, 영구 설정은 `/etc/selinux/config` 수정)

## SSL/TLS 인증서 체계 및 사설 웹 서버 웹 구축

- **SSL/TLS 개요**
    - HTTP, sFTP 등에서 교환하는 데이터를 암호화(TLSv2)하여 세션 가로채기를 방어함.
    - 네이버, 구글 등 대형 포털은 전 세계 브라우저에 탑재된 **공인 루트 인증서(CA)**를 구매하여 HTTPS 서비스를 제공함. 공인 인증서가 없는 사설 사이트는 브라우저에서 '신뢰할 수 없는 사이트' 경고를 띄움.
    - 외부 패키지나 인증서 키는 변조 방지(Integrity)를 위해 주로 시스템 내 키링(Keyrings) 공간인 `/etc/pki/tls/` 하위에 저장됨.
    - `openssl`이나 `gpg` 같은 도구는 오픈소스 기반으로 소스코드가 개방되고 무료로 쓸 수 있는 **CopyLeft** 철학이 적용되어 있음. 이 때문에 클라우드 인프라 구축 시 상용 Windows 시스템 대신 대부분 Linux 체제를 사용함.
- **주요 브라우저별 기기 인증서(CA) 확인 경로**
    - **Chrome**: `⁝` (우측 상단) > 설정 > 개인정보 및 보안 > 보안 > 기기 인증서 관리 > '신뢰할 수 있는 루트 인증기관' 탭
    - **Edge**: `...` (우측 상단) > 설정 > 검색창에 '인증서' 입력 > 인증서 관리 > '신뢰할 수 있는 루트 인증기관' 탭
    - **Firefox**: `≡` > Preferences > Advanced > Certificates > View Certificates... > Authorities 탭
    - **IE**: 도구 > 인터넷 옵션 > 내용 탭 > 인증서
- **mod_ssl을 이용한 사설 웹 서버 구축 프로세스**
    1. **개인키 생성**: `openssl` 명령어로 사설 개인키(`.key`)를 생성함.
    2. **인증서 발급 요청서(CSR) 생성**:
        - *명령어*: `openssl req -new -days 365 -key www.kahn.edu.key -out www.kahn.edu.csr`
        - 명령 실행 후 암호 문구(Passphrase)로 `rootoor`를 입력하고 진행하면 최종적으로 **`www.kahn.edu.csr` (인증서 요청서)** 파일이 생성됨.
    3. **사설 인증서(CRT) 발급**: 앞서 생성한 요청서(`.csr`)와 개인키(`.key`)를 바탕으로 x509 모듈을 사용해 최종 사설 인증서(**`www.kahn.edu.crt`**)를 생성함. (필요시 .key와 .crt를 합쳐 .pem 포맷으로 통합 가능)
    4. **인증서 파일 위치 지정**:
        - 리눅스 웹 서버 설정: `/etc/httpd/conf/httpd.conf`
        - 리눅스 SSL 설정: `/etc/pki/tls/openssl.cnf`
    5. **클라이언트 배포**: 사설 사이트이므로 발급한 `.crt` 파일을 각 클라이언트의 브라우저에 수동으로 등록해 주어야 경고 없이 `https://kahn.edu`로 정상 접근이 가능해짐.
        - *보안 참고*: 오픈소스 기반의 SSL 구축 및 운영 시 과거 알려진 **HeartBleed** 취약점 등에 대응할 수 있도록 패치 관리가 필요함.

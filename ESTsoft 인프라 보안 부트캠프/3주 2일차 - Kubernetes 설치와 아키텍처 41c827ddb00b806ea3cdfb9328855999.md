## Dockerfile 개념 및 문법

- **개념**
    - Bare Image(기본 이미지)에 필요한 패키지와 설정을 추가해 새 도커 이미지를 생성하는 DSL(Domain Specific Language) 스크립트 파일
    - 이미지 제작 과정을 **Dockerizing**이라 명명하며, Docker Hub 공식 이미지 대부분이 이 방식으로 제작된 결과물
- **주요 명령어**
    - `FROM` — 기반이 되는 베이스 이미지 지정 (예: `FROM ubuntu:latest`)
    - `RUN` — 이미지 빌드 시 실행할 명령어 (다수 사용 가능, `&&` 또는 `\`로 줄 연결)
    - `WORKDIR` — 작업 디렉터리 지정 (예: `WORKDIR /usr/app/`)
    - `ENV` — 환경 변수 설정 (`<키> <값>` 형식, 예: `ENV NODE_ENV products`)
    - `EXPOSE` — 컨테이너가 사용할 네트워크 포트 명시 (`TCP` 생략 가능, 예: `EXPOSE 80`, `EXPOSE 9999/udp`)
    - `ADD` / `COPY` — 호스트의 파일이나 디렉터리를 이미지 내부로 복사 (`<src> <dst>` 형식)
    - `ARG` — 이미지 빌드 시점에 전달받을 변수 설정 (예: `ARG port=8000`)
    - `ENTRYPOINT` — 컨테이너 시작 시 항상 실행되는 고정 명령어
    - `CMD` — 컨테이너 시작 시 실행할 기본 명령어 (다수 작성 시 **가장 마지막 `CMD` 하나만 유효**, `ENTRYPOINT`와 함께 사용 시 기본 인자 역할)
    - `#` — 주석 처리
- **Ubuntu 저장소 변경 팁**
    - `RUN apt update` 전에 `RUN sed -i 's/://ubuntu.com' /etc/apt/sources.list` 추가
    - 파일을 직접 열지 않고 `sed` 편집기를 통해 국내 서버 주소로 빠른 일괄 변경 가능

## 주요 Docker & Linux 명령어

- **명령어 치환 (`$()`)**
    - `$(명령어)` 형태로 괄호 앞에 `$`를 부착해 명령어의 실행 결과를 변수처럼 취급하는 방식
    - `docker rm -f $(docker ps -aq)` — 실행 중이거나 종료된 모든 컨테이너 강제 일괄 삭제
    - `docker rmi -f $(docker images -q)` — 모든 도커 이미지의 ID(`q`)를 불러와 강제 일괄 삭제
- **컨테이너 실행 및 포트 포워딩 (Port Forwarding)**
    - 명령어 예시 — `docker run --name website1 -v $(pwd):/usr/share/nginx/html:ro -p 8000:80 -d nginx:latest`
    - 동작 원리 — 외부 사용자가 호스트(Ubuntu)의 `8000`번 포트로 접속 시, 격리된 프로세스 환경인 내부 컨테이너(`website1`)의 `80`번 웹 서버 포트로 **Redirect(포트 포워딩)** 되어 웹 페이지 출력
    - 볼륨 마운트 — `v` 옵션으로 호스트 현재 디렉터리(`$(pwd)`)를 컨테이너 내부 경로에 읽기 전용(`ro`)으로 연결
- **파일 입출력 (`cat`)**
    - `cat abc.txt` — 파일 내용 조회
    - `cat > abc.txt` — 입력한 내용으로 새 파일 생성 (`Ctrl+d`로 저장 및 종료)
    - `cat >> abc.txt` — 기존 파일의 맨 끝에 내용 추가

## Kubernetes 개념 및 구조

- **정의**
    - 다수의 Docker 컨테이너를 배포·관리·확장하는 **컨테이너 오케스트레이션(Orchestration) 플랫폼** (약칭 **Kube** 또는 **K8s**)
- **클러스터 구성**
    - 단일 호스트(Ubuntu 1대) 실행 환경 — 학습용 **Minikube**
    - 다수 노드(Ubuntu 1, 2, 3...)로 구성된 **Cluster** 실행 환경 — 진정한 **Multi-node Kubernetes** (클러스터들의 집합이 **Cloud** 인프라 형성)
    - 역할 분리 — 전체 클러스터를 지휘·통제하는 **Control Plane(Master Node)**과 실제 애플리케이션이 실행되는 **Worker Node(Data Plane)**로 구분 (Hadoop의 NameNode와 DataNode 구조와 유사)

## 무정전 서비스 원리

웹 서버 Pod(컨테이너의 논리적 실행 단위) 5개(`replicas=5`) 배포 시 K8s의 핵심 동작 메커니즘

1. **Load Balancing (부하 분산)** — 5개의 Pod를 여러 Worker 노드에 적절히 분산 배치하여 실행
2. **Self-Healing (자동 복구)** — 특정 노드에서 실행 중인 Pod 1개 비정상 종료(Killed) 시, K8s의 감지를 통해 자동으로 새 Pod를 생성하여 항상 5개 유지
3. **Node 장애 대응 (Migration)** — 특정 노드(예: Node 1) 자체 고장 시, 해당 노드에서 실행되던 Pod들을 정상 작동 중인 다른 노드(Node 2 등)로 자동 재배치하여 서비스 중단 방지
4. **무중단 업그레이드 (Rolling Update)** — 애플리케이션 업데이트 시 설정 비율(`maxSurge` 등)에 따라 새 버전 Pod를 먼저 추가(+1개, 일시적 6개 실행)한 뒤 기존 Pod를 순차 종료하며 교체 (외부 사용자 관점에서 중단 없이 항상 5개의 웹 서버 정상 운영)

## IP 주소 대역 구조

- **노드 IP 대역 (호스트 물리/가상 머신)**
    - `192.168.100.0/24` 등 **Class C** 사설 대역의 주된 사용
    - 앞 24비트 네트워크 주소, 나머지 8비트(`2⁸ = 256`개 중 네트워크·브로드캐스트 주소 2개 제외) 할당으로 노드 수 최대 **254대** 제한
- **Pod IP 대역 (클러스터 내부 가상 네트워크)**
    - `10.20.20.0` 등 **Class A** 사설 대역(`10.0.0.0/8`) 범위의 활용
    - 첫 8비트 네트워크 주소, 나머지 24비트(`2²⁴ - 2 = 16,777,214`개) 호스트 할당 가능으로 노드별 서브넷 분할을 통해 수백만 개 Pod에 고유 IP 부여

## Vagrant를 이용한 K8s 실습 환경 구축 순서

실제 서버 3대 대신 호스트 Ubuntu(VMware) 내부에 **VirtualBox** 설치 후 **Vagrant**로 가상 노드 3대 자동 생성 및 **Ansible**(구성 관리 및 자동화 도구)을 통한 K8s 환경 일괄 배포 절차

1. **가상머신 이미지 준비**
    - `찐K8s_vagrant.zip` 압축 해제 후 `~.vmx` 파일 실행을 통한 VMware 내 Ubuntu 18.04 기반 가상머신 등록
2. **로그인 및 디렉터리 이동**
    - 계정(`hduser` / `hduser`) 로그인 후 터미널에서 `cd Desktop/kube` 경로 이동
3. **설정 확인 및 가상 노드 실행 (`vagrant up`)**
    - `cat -n Vagrantfile` 명령으로 `master` 1대, `worker-01`, `worker-02` 2대 구성 확인
    - `vagrant up` 실행을 통한 VirtualBox 및 Ansible 설치, 네트워크(NAT, Host-Only) 및 SSH 설정 자동 진행 (진행 중 장시간 정지 시 `Ctrl+c` 중단 후 `vagrant up` 재실행으로 마무리)
4. **상태 확인 및 Master 접속**
    - `vagrant status` 명령으로 3대 노드 모두 `running` 상태 확인
    - `vagrant ssh master`로 마스터 노드 접속 후 `sudo su` 입력을 통한 `root` 권한 획득 (Vagrant 이미지 내부 `/etc/sudoers` 설정에 비밀번호 생략 규칙 `NOPASSWD` 적용으로 별도 암호 없이 즉시 전환)

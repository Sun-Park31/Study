## 가상화(Virtualization) 및 가상 머신(VM)의 본질 ★

<aside>
💡

- 가상머신 생성 도구 분류
    - **클라이언트(호스트형) 가상화 :** VMware Workstation, Oracle VirtualBox, MS VirtualPC 등
    - **엔터프라이즈 서버 가상화 :** VMware vSphere(ESXi), Citrix Hypervisor 등
- **VM의 특징 :** 하드웨어 독립적인 **'파일(File)' 형태**로 존재하므로 복사, 이동, 삭제, 백업(스냅샷)이 극도로 자유로움.
    - *효율성 :* 마스터 이미지(Win 10/11) 1대를 구축한 후 100대를 복사(복제)하면, 물리 장비 100대 구매 없이 독립된 고유 IP와 작업 그룹을 가진 대규모 PC 환경을 유무선 인프라에 즉시 배포 가능.
    - ⚠️ *운영 차이 :* VMware 등의 전통적인 하이퍼바이저 기반 VM과 Docker 등의 컨테이너 이미지, AWS/Azure 등의 클라우드 인스턴스는 자원 할당 및 커널 공유 방식에서 큰 기술적 차이가 있음.
- **OS별 커널 내장 하이퍼바이저 (Hypervisor) :** 가상머신을 생성하고 호스트 자원을 분배하기 위해 각 운영체제(OS)는 고유의 내장 도구를 사용함.
    - *Linux 환경 :* **KVM (Kernel-based Virtual Machine)** 도구를 커널 레벨에서 기본 활용함.
    - *Windows Server 환경 :* MS의 가상화 기술인 **Hyper-V** 도구를 활성화하여 가상머신을 생성함.
- **서버 상태 완전 저장 (스냅샷 및 가상화의 이점) :** VMware나 Norton Ghost 같은 프로그램은 서버 머신의 현재 OS 상태, 메모리, 설정 그대로를 이미지화하여 저장(스냅샷)할 수 있음.
    - 서버에 예기치 못한 치명적인 장애나 에러가 발생하더라도, 스냅샷 시점으로 언제든지 깨끗하게 되돌릴 수 있는 강력한 무기가 됨.
    - Windows OS에서도 부팅 실패 시 안전하게 직전의 정상 시점으로 되돌아가는 **'Last Known Good'**(가장 최근에 성공한 좋은 구성) 환경을 오래전부터 내장하여 제공해 왔음.

## VMware 가상 네트워크 및 인프라 이중화 ★

가상머신(Guest OS)이 호스트 PC와 가상 장치들을 거쳐 외부 인터넷과 통신하는 흐름 및 고가용성 설계 구조.

- 가상 네트워크 4가지 모드
    - **NAT (Default) :** 가상 라우터 및 가상 스위치를 경유하여 **호스트 PC의 IP를 변환(NAT)**해 외부 인터넷과 통신. (가상 게이트웨이 주소는 통상 `~.2` 사용)
    - **Bridge :** 호스트 PC의 물리 랜카드(NIC)와 동등한 자격으로 외부 공유기/네트워크에서 **직접 IP를 할당받는** 방식.
    - **Host-only :** 외부 인터넷 및 호스트 외곽과 차단되고, 내부 VM들끼리만 통신할 수 있는 **폐쇄망** 환경.
    - **No Network :** 네트워크 어댑터 연결 자체를 차단.

<aside>
💡

- 패킷 흐름 및 시스템 이중화 (Fail-Safe/Safe-Failure) ★
    
    [ Guest VM (Win Server / Ubuntu) ] ➡️ [ 가상 Switch ] ➡️ [ 가상 Gateway (.~2) / NAT ] ➡️ [ 호스트 물리 NIC ] ➡️ [ 인터넷 ]
    
    - **Channel Bonding / NIC Teaming:** 효율성 증대와 선로 장애 극복(**Fail-Safe / Safe Failure**)을 위해 여러 개의 물리 랜카드(NIC) 또는 케이블을 논리적으로 하나로 묶어 대역폭을 확장하는 기술.
    - **Multi-homed Machine:** 한 대의 서버에 여러 개의 물리 NIC를 장착하여 두 개 이상의 서로 다른 네트워크 대역을 동시에 서비스하는 구조.
    - **고가용성 4대 원칙:** 시스템 인프라 설계 시 속도 유지와 무중단 서비스를 위해 **Round Robin(부하 분산 알고리즘), Fault Tolerance(결함 허용), Load Balancing(부하 분산), Redundancy(이중화)** 메커니즘을 반드시 반영해야 함.
- DHCP 및 DNS 가상 인프라 기본 동작 메커니즘
    - **DHCP (Dynamic Host Configuration Protocol) :** 자신의 네트워크 영역에 속한 일반 사용자 호스트 컴퓨터에게 **5가지 핵심 정보(IP 주소, 서브넷 마스크, 게이트웨이 주소, DNS 서버 주소, DHCP 서버 주소)**를 자동으로 중앙 배포하고 관리하는 프로토콜.
    - **DNS (Domain Name System) :** 인터넷 통신의 본질은 숫자 IP 주소 체계이므로, 사람이 이해하는 문자 주소(`://naver.com`)를 컴퓨터가 이해하는 숫자 주소(`203.100.100.100`)로 상호 변환해 주는 **이름 확인(Name Resolution)** 서비스.
    - *가상화 네트워크 융합 :* VMware Workstation 환경에서 가상 머신들이 외부와 정상 통신하기 위해 지정하는 가상 게이트웨이 및 내부 DNS 주소는 대개 `~.2`로 수렴하며, 외부 통신 연결성 확보를 위해 공용망인 KT DNS(`168.126.63.1`)나 Google DNS(`8.8.8.8 or 8.8.6.6`)를 다중 지정하여 사용함.
</aside>

## Windows Server의 Active Directory(AD) 논리 구조 ★

독립형 서버(Standalone)에 AD 역할을 올리고 도메인 컨트롤러(DC)로 승격하여 시스템을 중앙 관리하는 체계.



- **도메인 컨트롤러(DC) 승격 :** 일반 서버에서 시작 ➡️ 실행 ➡️ **`dcpromo.exe`** 명령어를 실행하여 도메인 서버로 승격.
    - *주의 :* 일반 서버에서 DC로 승격하는 과정은 **시스템 레벨에서 비가역적(Not Reversible / 하이드레이드 불가)**이므로 신중해야 함.
    - *참고 (파일 시스템 변환) :* 과거 `FAT32`에서 `NTFS`로 변환된 드라이브를 유실 없이 되돌릴 때 `Norton's Partition Magic` 같은 유틸리티를 ~~편법으로~~ 사용하기도 했음.
- AD 핵심 용어 및 구조
    - **PDC / BDC :** 도메인의 안정성을 위해 주 컨트롤러(Primary)와 백업 컨트롤러(Backup)로 이중화 운영.[보편적 DC는 이 둘로 이루어짐.]
    - **GC (Global Catalog) :** 도메인 포레스트 내의 모든 개체(사용자, 컴퓨터, 자원)에 대한 핵심 정보만 모아둔 일종의 '전화번호부(인덱스)' 역할을 하여 자원 검색을 최적화함.
    - **OU (Organizational Unit) :** AD 구조 내에서 관리 권한을 위임하고 그룹 정책(GP)을 적용할 수 있는 **최하위 조직 단위**.
    - **RODC (Read-Only Domain Controller) :** 보안이 취약하거나 관리자가 없는 소규모 지사(예: 제주)에 배치하는 읽기 전용 DC. 본사(부산 등)의 상위 도메인에서 데이터를 일방향으로만 동기화 받아 도메인 무단 수정을 방지함.
    - ⚠️ *DNS 필수 연계 :* AD 구축 시 도메인 이름(예 : `kahn.edu`) 조회를 처리해 줄 **DNS 서버 설정이 반드시 동반**되어야 외부 및 내부 사용자가 서비스를 정상적으로 찾을 수 있음.
- 각 운영체제 및 플랫폼별 그룹 권한 관리 비교
    - *Windows Server:* **Domain Local Group, Global Group, Universal Group**의 3단계 도메인 스코프 범주로 그룹을 세분화하여 권한을 위임함.
    - *Linux 시스템:* 그룹(Group)을 생성하고 해당 그룹에 특정 디렉터리 권한을 부여한 뒤, 사용자 계정들을 해당 그룹에 할당하여 동일한 권한을 행사하게 함.
    - *Database (Oracle 등):* 그룹 대신 **Role(역할)**이라는 개념을 사용함. Role을 생성하여 데이터베이스 접근/수정 권한을 담아두고, 사용자 계정들을 Role에 귀속시켜 대량의 권한을 관리함.

## Windows Server 2016의 신기능 및 리눅스 비교

기존 2008 서버 대비 클라우드, 가상화, 보안 관점 대폭 강화, Linux의 주요 기능들과 일대일 대칭 구조.

- 특징
    - **원격 데스크톱 서버 전환:** 과거의 '터미널 서버' 개념을 완전히 탈피. 사용자의 제어판 숨기기, 시작 페이지 고정, 바탕화면 통제 등은 **그룹 정책(GP)**을 통해 훨씬 고도화된 방식으로 제어.
    - **Nano Server:** GUI가 전혀 없는 기존 `Server Core`보다 훨씬 가볍고 미니멀한 초경량 OS. 가상머신 재시작 및 이미지 복제가 매우 빨라 클라우드 가상화 환경에 최적화됨. (Core 서버는 서버에서 직접 CLI로 작업하지만, Nano 서버는 100% 원격 가상 환경에서 관리함).
    - **Windows Container:** Docker 기술을 윈도우 커널에 응용한 가상화 기법. 하드웨어를 통째로 가상화하는 `Hyper-V 컨테이너(VMware 방식)`보다 훨씬 가볍고 배포가 용이한 `Windows Server 컨테이너(Docker 방식)`를 지원함.
    - **Direct Access & Dynamic Access:** 외부에서 복잡한 로그인 없이 사내 VPN에 자동 연결하는 기술(재택근무/원격진료에 특화) 및 다중 파일 서버에 동일한 데이터 거버넌스 정책을 동시 적용하는 기능(**Linux의 NIS 기능과 유사**).
    - **ReFS (Resilient File System):** 데이터의 가용성과 무결성을 극대화하여 손상 시 스스로 탄력적으로 복구하는 차세대 파일 시스템(**NTFS의 상위 호환**).
    - **IPAM (IP Address Management):** 네트워크 내 유동/고정 IP 현황을 중앙에서 완벽하게 모니터링하고 추적하는 도구(**보안 NAC 솔루션과 유사**).
    - **유연한 저장소 관리:** 대용량 디스크를 쪼개 쓰거나 작은 디스크를 거대 풀로 묶어 쓰는 가상화 기술 적용(**Linux의 LVM 기능과 유사**).

## WDS를 이용한 대규모 무인 배포 시스템 ★

서버 관리자가 수많은 워크스테이션이나 노트북에 OS를 동시에 자동 설치하는 네트워크 아키텍처

- **WDS (Windows Deployment Services) :** 서버에 운영체제 이미지(ISO)를 탑재한 후, 네트워크망을 통해 수십~수백 대의 클라이언트 PC에 OS를 원격으로 밀어 넣는(Deploy) 배포 서비스.
- **Unattended Installation (무인/자동 설치) :**
    - 클라이언트 PC가 부팅될 때 **RARP 또는 DHCP** 프로토콜로부터 네트워크 IP 및 부팅 파일(PXE)을 자동으로 할당받아 배포 서버에 접속함.
    - 엔지니어가 수동으로 세팅값을 클릭할 필요 없도록, 설정 정보를 사전에 기록한 **응답 파일(Answer File)**을 WDS 서버가 클라이언트에 함께 주입하여 **All Automatic(전체 자동화)** 무인 설치를 수행함.

## 인프라 기초 관리 (서버 사양, 디스크, 인증)

- 관리 방법
    - **서버 보안 최소화 원칙 :** 서버에는 해킹 위협을 최소화하기 위해 Web, FTP, DB 등 꼭 필요한 서비스(약 16가지 범주)만 미니멀하게 설치함. 용량이 큰 메일/DB/웹 서버는 단독 서버로 떼어내고, 가벼운 DHCP/DNS/Proxy 등은 하나의 서버에 통합 운영하는 것이 정석.
    - **IP 운영 원칙:** 일반 워크스테이션 클라이언트는 DHCP를 통한 Dynamic(동적/자동) IP를 사용해도 무방하지만, **서버는 사용자가 언제나 고정된 주소로 접속해야 하므로 반드시 Static(정적/수동) 고정 IP로 설정**해야 함.
    - **실습 환경 최소 사양:** 정보보안 및 멀티 가상머신 실습을 위해 호스트 PC는 최소 **RAM 16G 이상, 저장공간 1TB 이상** 확보 권장 (Docker나 클라우드 기반 VM은 더 작은 스펙으로도 구동 가능).
    - **데이터 분리 및 복구 보안:** 서비스 설정 및 구성 파일은 OS 드라이브(`C:\`)가 깨질 때를 대비해 타 드라이브(`D:\`)에 이중화 백업해야 하며, 복구용 백업 파일에는 유출 방지를 위해 **'백업비번'**(`votmdnjem`)과 같은 안전한 비밀번호 설정을 강제해야 함.
    - **스토리지 인터페이스 역사:**
        - `IDE:` 마더보드 리본 케이블로 마스터/슬레이브 점퍼를 세팅하던 구형 방식 (최대 4개 장치).
        - `SATA:` 데이터 유연성을 확보하고 직렬(Serial) 방식으로 전송 속도를 높인 현재의 표준 규격.
        - `SCSI:` IDE의 한계를 극복하고 최대 15개의 고속 장치를 리본 케이블로 연결하도록 설계된 과거 서버 전용 고성능 규격.
    - **이기종 통합 인증:** Windows, Linux, UNIX 시스템이 사내 망에 혼재되어 있을 때 전사적인 단일 인증(Authentication) 체계를 구축하기 위해 최근에는 **Kerberos(케르베로스) 인증 서버**를 표준으로 채택하는 추세이며, 이와 연계된 프로토콜로 **LDAP, RADIUS, NIS** 등이 있음.
    - **하드웨어 자원 점검 과정 (POST) :** Router, Switch, Windows Server, Linux 등 네트워크와 서버를 구성하는 거의 모든 하드웨어 장치는 전원이 켜질 때(부팅 시) 자신의 물리적 하드웨어 상태와 기본 소프트웨어 설정을 자체 점검하는 **POST (Power On Self Test)** 과정을 거침. (관리자 설정에 따라 화면에 안 보이게 숨길 수 있음).
    - **위험 관리 및 시스템 배포 안정성 확보 (파일럿 시스템) :** 대규모 기업 인프라 환경에서는 OS 업데이트, 보안 패치, 소프트웨어 변경 사항을 실제 가동 중인 실서버에 바로 적용하지 않음.
        - 조직의 서버 및 클라이언트 시스템 환경과 똑같이 복제한 2~3대 규모의 **Pilot System(파일럿 시스템/테스트 베드)**을 사전에 먼저 구성함.
        - 이 파일럿 시스템에 업데이트나 패치를 우선 적용해 보고, 아무런 충돌이나 에러가 발생하지 않는 것이 확실하게 검증된 상태에서만 최종적으로 실제 운영 서버(실서비스망)에 순차 배포하여 다운타임(장애)을 철저히 예방함.
    - 핫·웜·쿨 사이트 (Hot/Warm/Cold Site)
        - **핫 사이트 (Hot Site) :** 본사와 백업 센터가 24시간 실시간으로 데이터를 동기화. 본사가 터지면 **몇 분/몇 초 만에** 바로 바통을 이어받아 정상 서비스 가능. (가장 비쌈)
        - **웜 사이트 (Warm Site) :** 중요 데이터만 주기적으로(하루에 한 번 등) 백업. 본사가 터지면 장비를 켜고 복구하는 데 **수 시간에서 수 일**이 걸림. (중간 비용)
        - **쿨 사이트 (Cold Site) :** 데이터 센터 건물과 기본적인 전력 선로 틀만 갖추어 둔 텅 빈 공간. 장애가 나면 그때서야 장비를 사고 백업 테이프를 가져와서 처음부터 재구축해야 하므로 **수 주~수 개월**이 걸림. (가장 저렴)

**VM**

하드웨어, 운영체제같은 것들을 가상으로 구동 가능함.

호스트형(클라이언트 느낌), 서버형, 둘 모두 가능한 경우 다 존재.

윈도우는 Hyper-V, 리눅스는 KVM

</aside>

<aside>
❗

**Channel Bonding / NIC Teaming**

망가질 수도 있으니 여러개 묶어서 고장에 대비한다!

</aside>

<aside>
❗

**AD와 DC**

회사 하나를 예로 들자.

직원들에 관한 정보 모음의 제목이 도메인.

회사 직원들에 관한 정보를 DB로 만들어 놓은 것이 AD.

그러한 AD를 갖고 있으면서 인증, 인가 해주는 PC가 DC.

독립된 일반 윈도우 서버에 **`dcpromo.exe`** 명령 내리면 그 서버 컴퓨터는 DC가 됨.

(가장 작은) OU - 도메인 - 트리 - 포리스트 (가장 큰)

도메인 제목 내부에 더 작게 구분된 OU(보통 작업 단위를 위함)

부모 자식 관계의 도메인을 지닌 트리

트리가 모인 포리스트

포리스트가 모인 사이트

</aside>

<aside>
❗

**WDS**

서버에 운영체제 이미지 업로드해서 브로드캐스팅 해버림.

반복작업에 인간 부족하면 한 번에 처리 가능(모두 같은 환경이라는 가정 하에 한 명이 하나의 작업 하니 모두 같은결과)

</aside>

    - 서버나 DB 마비됐다고 다 포기하고 포트 다 개방하고 하는게 아니라, 닫을 수 있는 건 다 닫고, 막을 수 있는 건 다 막아야 그래도 덜 망해..

**스토리지 보편적 종류**

- **IDE :** 옛날 시골의 넓지만 덜 닦인 자갈길 (느린 병렬), 넓적했던 회색 리본 케이블
- **SATA :** 요즘 도심의 쾌적하고 빠른 왕복 고속도로 (빠른 직렬), 지금 얇은 선 하나
- **SCSI :** 옛날 대형 화물 트럭 전용 전용 차선 (서버용 다중 연결), 케이블 하나에 디스크 15개도 가능…
